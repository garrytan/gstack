# Idea 001: /toolstack — Approved Tool Stack Discovery & Policy Browser

## Raw Dump
Tool stack discovery skill. Will point to a repo or a data store and advise the
user what tools we have available and can be used according to policy. This may
be better as a prototype app.

## Essence
A discovery layer for the org's approved tooling landscape. Points at a source
of truth (a repo, a data store, a registry) and tells users: what tools exist,
what's approved for use, what's the policy around each one, and how to get access.
Could be a terminal skill for quick lookups OR a full prototype web app with
searchable UI, filters by category/team/approval-status, and policy links. Maybe
both — skill for terminal, app for rich browsing.

## Interesting Because
- Every org has this problem: "can I use Tool X?" requires asking 3 people and
  waiting 2 days. This makes the answer instant and self-serve.
- The "point at a repo or data store" approach is key — it's not hardcoded
  knowledge in the skill, it's dynamic from a live source of truth. Update the
  registry, the skill/app reflects it immediately.
- Sits ABOVE /mcp-catalog: MCPs are one tool category. This covers everything —
  approved SaaS, internal platforms, APIs, dev tools, design tools, the lot.
- Policy integration is the differentiator: not just "this tool exists" but "you
  are/aren't allowed to use it, here's the policy, here's how to request access."
- Natural governance tie-in: /governance can reference toolstack approvals during
  checkpoint reviews.
- The prototype app version could have: search + filter, approval status badges,
  team-specific views, request-access buttons, policy document links, usage stats.
- Could auto-discover tools from repos (scan package.json, Dockerfile, CI configs)
  and flag unapproved dependencies.

## Expansion Seeds
- What if the app auto-scanned team repos and flagged unapproved tool usage?
  "Team X is using Tool Y which isn't in the approved registry — flag for review."
- What if there was a "request access" workflow built in? User finds a tool,
  clicks request, auto-routes to the right approver with context pre-filled.
- What if it showed tool popularity: "Used by 12 teams, 4 pending requests this
  month" — helps governance understand demand for tools not yet approved.
