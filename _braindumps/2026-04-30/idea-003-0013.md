# Idea 003: /skill-optimize — Autonomous Skill Improvement Loop (Karpathy-style)

## Raw Dump
Skill optimization loop. Sets up a number of agents: Agent 1 tests the skill
against a test suite, then scores against eval criteria set by the user. Then an
analyst agent runs that assesses this and diagnoses failures etc and creates a
strategy to fix. Then a new agent stands up and fixes the highest priority item
and then cyclically runs this as a loop — build test build test etc. As score
tests run, if score keeps improving the loop keeps running, if the score dips or
remains static, it stops. This is based on Karpathy's auto research but without
the hardware. Can we do it? What do we need to run this well? And most NB how do
we make this a collaborative thing amongst groups of users?

## Essence
Autonomous iterative skill improvement. A multi-agent loop inspired by Karpathy's
auto-research concept: (1) Tester agent runs the skill against a test suite and
scores it against user-defined eval criteria, (2) Analyst agent diagnoses failures,
identifies patterns, and creates a fix strategy with priorities, (3) Fixer agent
implements the highest-priority fix, (4) Loop back to step 1. Convergence logic:
keep running while score improves; stop when score plateaus or regresses. The
collaborative dimension: multiple users contribute eval criteria, test cases, and
fix strategies — the loop benefits from collective intelligence.

## Interesting Because
- It's Karpathy's auto-research applied to SKILL QUALITY instead of ML research.
  Same principle: autonomous iteration with a fitness function. Brilliant transfer.
- The three-agent architecture maps perfectly to existing patterns:
  - Tester = /eval-run (already exists!)
  - Analyst = /investigate + /root-cause (diagnosis skills)
  - Fixer = /skill-forge (already builds skills)
  You're orchestrating existing skills into a higher-order loop.
- The stop condition is the key insight: score-based convergence. No infinite loops,
  no wasted compute. The system knows when it's "done" — when improvement plateaus.
- "Without the hardware" is important — this runs on Copilot CLI agents, not GPU
  clusters. Each iteration is an LLM call, not a training run. Cheap and fast.
- The collaborative angle is what makes this not just "auto-fix" but "team sport":
  - Multiple users contribute test cases (diverse perspectives)
  - Users vote on which failures matter most (priority calibration)
  - Fix strategies are visible to the team (learning from each other)
  - Score improvements are shared (collective achievement)
- What you need to run this well:
  1. Solid eval criteria (/eval-create — already have this)
  2. A test suite (structured test inputs + expected outputs)
  3. Agent orchestration (the loop controller that manages handoffs)
  4. Score tracking over time (convergence detection)
  5. Git integration (each fix is a commit, easy to revert if score drops)
- Could become the quality engine for the ENTIRE Skillz library. Run it across
  all 62 skills nightly — continuous quality improvement while you sleep.
