# Idea 002: /ai-guides — How-To Guide Library for AI Capabilities

## Raw Dump
How-to guides for building various AI capabilities such as standing up a new MCP,
building skills (abstracted level from skill-forge), setting up a RAG pipeline and
making it reusable, standing up AI agents (focus on the capabilities of the Google
Vertex/Gemini enterprise platform) etc.

## Essence
A structured library of opinionated how-to guides that enable teams to build AI
capabilities themselves. Not theoretical — hands-on, step-by-step, "do this and
you'll have a working thing." Covers the core AI building blocks: MCPs, skills,
RAG pipelines, AI agents. Platform-opinionated toward Google Vertex/Gemini as the
enterprise backbone. Each guide is standalone, reusable, and maintained. The eGain
MCP setup guide already written is the first instance of this pattern.

## Interesting Because
- This is the scale play. You can't be the bottleneck for every team wanting AI
  capability. Guides let them self-serve while staying on the sanctioned path.
- Platform-opinionated (Vertex/Gemini) means teams don't waste time choosing —
  they follow the golden path. Reduces decision fatigue and fragmentation.
- Each guide is a distinct AI building block:
  1. **Standing up an MCP** — stdio/SSE transport, auth, tool registration, testing
  2. **Building skills** — abstracted from /skill-forge (the human-readable version)
  3. **RAG pipeline** — embeddings, chunking, vector store, retrieval, reuse patterns
  4. **AI agents** — Vertex AI agents, Gemini function calling, orchestration
  5. **Prompt engineering** — could extend here too
- "Making it reusable" is the key phrase — not one-off demos but templates that
  teams can fork and customize for their domain.
- The eGain guide (~/.copilot/guides/egain-mcp-setup.md) is proof this works.
  Same format, same depth, just generalized across capability types.
- Naturally feeds /toolstack: each AI capability becomes an entry in the approved
  tool registry with its how-to guide linked.
- Could live as markdown in a repo (developer-friendly) AND rendered as a portal
  section (browseable by non-devs).

## Expansion Seeds
- What if each guide had a "quickstart" (5 min) and a "deep dive" (30 min) version?
  Same content, different depth. Busy people get the quickstart, curious people
  go deep.
- What if the guides were interactive — user runs a command and the guide walks
  them through it step by step, verifying each step works before proceeding?
  Like a tutorial mode built into Copilot CLI.
- What if completed guides auto-registered the new capability? Finish the MCP guide
  → MCP appears in /mcp-catalog. Finish the agent guide → agent appears in /toolstack.
