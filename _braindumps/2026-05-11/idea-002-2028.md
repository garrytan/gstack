# Idea 002: Data Flow — Structured + Knowledge Paths

## Raw Dump
Structured Data Path: Each product team follows this same pipeline with their own source data. Ingestion → Bronze (raw, cataloged as-is) → Silver (cleaned, transformed, aggregated) → Gold (validated, business-ready, the layer agents should trust) → BigQuery (Gold-layer data lands here for structured querying). Query Agent queries through the Semantic Layer or directly against parameterized table functions where semantic layer coverage is incomplete. RBAC enforced on both paths.

Knowledge Path (RAG): Product docs, help articles, and knowledge base content stored in a GCP Bucket. RAG Agent retrieves relevant documents using Vertex AI for embedding and ranking, generates contextual response, passes back through orchestrator. Each product team provides its own knowledge base documents. The pipeline is shared.

Access Control: RBAC through parameterized table functions in BigQuery — automatically scope results to only rows the user is authorized to see (based on email and location). Action Engine owns RBAC enforcement across both query paths for consistency. Semantic layer enforces business definitions and access rules where coverage exists. Agents scoped to specific domains — CFO Agent cannot access marketing data. Agent boundaries enforced through configured tool and API access per agent type.

Key Dependencies: Semantic Layer and Gold-layer data delivery from DLAK is on the critical path. Vertex AI licensing must be in place for RAG to scale beyond POC. Source system API quality directly impacts what agents can do and how fast new teams onboard. Each product team is responsible for the quality of their source data.

## Essence
Two parallel data paths — structured (Bronze→Silver→Gold→BigQuery) and knowledge (GCP Bucket→Vertex AI RAG) — feed into a shared agent orchestration layer. RBAC is enforced at three distinct levels: query, semantic, and agent boundary. The platform is shared; the data and docs are each team's responsibility.

## Interesting Because
The "each team owns their data quality" principle is quietly load-bearing. The platform can't be blamed for bad outputs if the source data is bad — but it also means onboarding speed is gated by things Action Engine doesn't control. The three-layer RBAC model (query → semantic → agent boundary) is elegant because it means no single point of failure on access control — but it also means three places something could go wrong or drift out of sync.
