# Idea 001: Constraint Mitigations — Action Engine

## Raw Dump
Platform validated against one vertical so far. Designed for extensibility; second team (MyAccount) validates in Phase 2.

No autonomous financial transactions. Approval workflows built into agent response patterns from day one.

Semantic layer coverage is incomplete. RBAC enforced on both query paths. Coverage expanding over time.

Agent framework limited to proven types so far. Plugin architecture allows new agents without rearchitecting.

## Essence
Four known constraints on the Action Engine, each with a deliberate mitigation already baked in. The pattern: don't hide the limitation — design around it from day one and let Phase 2 prove the extensibility.

## Interesting Because
This isn't defensive — it's a maturity argument. "We know what we don't know, and we've architected for it." That's a fundamentally different posture than most platform pitches, which oversell coverage and underplan for gaps. The approval-workflow-first approach to financial transactions is especially sharp — it means the trust model is built before the risk, not retrofitted after an incident.

## Threads
→ Exec Summary (2026-05-11): Dual-track strategy — Genius proves it, Platform makes it reusable. These mitigations are the honest version of what "proving it" actually involves.
