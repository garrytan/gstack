The severe items share two patterns:

1. **Shell assumptions that break real users.** Sourced helpers assume bash (macOS default is zsh, and Claude Code's Bash tool runs it), and reply templates put untrusted text inside double quotes, where backticks run as commands.
2. **Failures reported as the wrong thing.** A Codex usage limit reads as "inconclusive; proceeding", an oversize autoplan journal reads as a retryable identity failure, a shell-built autoplan init reads as "init missing", and a Windows `browse chain` with piped input exits 0 having run nothing.

### Release promises (the finish line)

- **P1. Codex outside voice works from zsh.** Every sourced gstack helper locates itself correctly when sourced by bash or zsh, from any working directory. A free test sources each one under both shells, and CI installs zsh so the test cannot skip there.
- **P2. Untrusted text never runs as shell.** No generated skill passes reviewer, diff or error text to a command inside double quotes. A lint fails on the pattern.
- **P3. Every failure names its real cause and its real fix.** Codex quota, oversize journals, shell-built autoplan inits, Windows chain input, Windows Docker and Windows browse dependencies each get a specific message with a fix line, documented in `docs/troubleshooting.md` or `docs/autoplan-guard-troubleshooting.md`.
- **P4. A red paid eval gets measured and fixed, not rerun blindly.** /ship runs the measure-then-fix loop from #3034 (approved 2026-10-05), and the weekly periodic red (#3038) is fixed with that loop.

- **CEO-12 (A3: free text never enters a shell command).** The rule is structural: in a generated bash block, a free-text placeholder (bodies, titles, messages, error output, reviewer or diff text) may appear only as the contents of a file whose path came from `mktemp`; the command gets `--body-file`, `-F body=@file` or `--title "$(cat "$file")"`. A bash block creates the private path with `mktemp`, the agent writes the text to it with the host's file-write tool, and the next block uses it. There is no heredoc fallback: if a host cannot write the file, the post is left unsent and the skill says so. Identifier placeholders that do enter commands (branch names, paths, PR numbers, comment ids) are on a reviewed allowlist, each with a validation grammar the skill applies before use (for example a branch name matching `^[A-Za-z0-9._/-]+$`); a value that fails its grammar is not used. The lint fails on any non-allowlisted placeholder in a command argument of any command, in any quoting (double, single, or an unquoted heredoc), and reads `\\` continuation lines as one command. Hostile-payload tests run through the real generated text: a body containing backticks, `$(...)`, an apostrophe and a line equal to a common heredoc delimiter, and a branch name containing `;`.
