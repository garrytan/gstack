1. **[Severity: High] One operating environment is being treated as a market.** The 27 threads describe two related repositories, one coordinator pattern, and one cloud environment—not 27 independent customer validations. Thirteen threads stopping after installation does not establish whether installation, workflow relevance, latency, or preference for existing tooling caused abandonment. Before funding B–D, test a minimal headless workflow across unrelated repositories and measure repeat usage, operator interventions, completion time, and cost against their existing workflows.

2. **[Severity: Critical] “A tree that passed never gets another gate” is an invalid release promise.** B3 treats equality modulo stamp paths as sufficient to refuse another gate, although runtime, dependencies, test selection, model configuration, and external state can change without changing that tree. Existing reuse explicitly requires complete input and environment identity, trusted receipt provenance, and bounded age; unknown inputs disable reuse ([scripts/eval-input-cache.ts:4](/workspace/gstack/scripts/eval-input-cache.ts:4), [scripts/eval-input-cache.ts:63](/workspace/gstack/scripts/eval-input-cache.ts:63)). Stamp-path globs also do not prove that every change within those files is behaviorally irrelevant. Replace P3 with per-check reuse under the existing identity contract, retaining release-specific freshness requirements and checks of the final stamped artifacts.

3. **[Severity: High] Machine-readable output is being confused with independently verifiable work.** Six files and derived counters can make an incomplete review internally consistent: an omitted finding disappears from both the findings file and its totals. The snapshot implementation explicitly distinguishes input identity from evidence that a reviewer consumed it, while plan-review records bypass the stronger diff-review binding path ([bin/gstack-autoplan-snapshot.ts:659](/workspace/gstack/bin/gstack-autoplan-snapshot.ts:659), [lib/review-evidence.ts:183](/workspace/gstack/lib/review-evidence.ts:183)). A4 lacks a versioned run manifest binding required phases, reviewer outcomes, decisions, input hashes, and artifact completeness. Make that manifest and a deterministic completion validator the primary deliverable; test interrupted runs, missing reviewers, stale artifacts, and omitted findings before promising that parents need only `jq`.

4. **[Severity: High] Session mode does not solve host compatibility.** D2 dismisses a host adapter by examining question capabilities, but host identity already determines which outside reviewer executes: Codex renders select Claude Code, while other renders select Codex ([scripts/resolvers/outside-voice.ts:8](/workspace/gstack/scripts/resolvers/outside-voice.ts:8)). 6. **[Severity: High] The queue design assumes version churn must be managed rather than eliminated.** B1–B7 build a release coordinator spanning predecessor merges, version allocation, historical text rewriting, generated files, and a second repository. The existing allocator already solves collision avoidance by advancing beyond claimed versions; that is different from stamping the next item against main at merge time ([bin/gstack-next-version:92](/workspace/gstack/bin/gstack-next-version:92)). The plan does not compare this machinery with assigning versions after merge, separating release metadata from feature PRs, or delegating stamping entirely to the repository’s release tool. Prototype those alternatives first, and remove generic historical-text rewriting and cross-repository mutation unless their necessity and recovery semantics are demonstrated.

8. **[Severity: High] Repository policy files acquire authority the plan never defines.** B1, B2, and B4 introduce executable commands and cross-repository writes under a workflow advertised as unattended, but containment of a JSON file does not establish trust in its commands or mirror target. Compare current and condensed workflows on a fixed, held-out incident panel, and gate on unresolved consequential findings rather than row presence or a resampled overall score.

11. **[Severity: Medium] The install verdict still lacks a definition of intended readiness.** A1 defaults requirements to installed hosts, which cannot reveal a missing intended host unless the caller already knows to request it; checking a patch heading establishes presence, not behavior. Runtime discovery also mixes compatibility requirements with CI selections: this repository declares Bun `>=1.4.2`, while its runtime helper separately distinguishes a security floor and supported minimum ([package.json:80](/workspace/gstack/package.json:80), [bin/gstack-bun-version.sh:10](/workspace/gstack/bin/gstack-bun-version.sh:10)). 12. **[Severity: High] Default contributor rewriting undermines the maintenance model.** D3’s prescribed output offers `supersede` or `decline`, omitting acceptance of a correct external implementation; D10 makes this treatment the default based on authorship. Reimplementing working contributions adds maintainer load precisely while this wave creates more tools, schemas, and platform obligations to maintain. Evaluate contribution behavior and evidence under the same acceptance criteria as maintainer changes, preserve a direct accept path, and reserve rewriting for demonstrated architectural or quality problems.
