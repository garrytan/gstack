### Competitive benchmark: how Claude Code, Codex, and Capy natively expose structured subagent output

- **Claude Code** subagents (Task/Agent tool) return a single free-text result to the parent; structured output exists only when the prompt asks for JSON and the parent parses it, with no schema or validator. `claude -p --output-format json` wraps the final message in a typed envelope (`result`, `session_id`, cost) but the content is still prose. gstack's B0 (`run.json` manifest + `schema_version` + validator) is ahead of the harness: it is the only one of the three that gives a parent a deterministic completion check.
- **Codex CLI** `codex exec` streams JSONL events and exits with the agent's status; the final message is text. There is no artifact manifest. gstack's `GSTACK_RESULT:` line plus files is comparable to Codex's last JSONL event; the gain is files with hashes a parent can validate later.
- **Capy** subagents end with a completion summary (`message_agent` final), a `tools.subagent.get` summary field, and files attached by path; `pr_create` gives a PR with checks and findings a parent reads through `tools.pr.getFindings` as structured rows. The pattern Capy already uses, identifiers first then prose and a typed findings list, is the pattern C5 and B2 adopt.
