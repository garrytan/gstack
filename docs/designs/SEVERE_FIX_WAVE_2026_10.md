# gstack severe fix wave (October 3, 2026): no silent failures, nothing lost, every host works

## Implementation plan

### Context

Base: origin/main `ac20ef1e1` (v1.91.16.0). Main CI is green. The weekly periodic eval lane and gate census have been red for five straight weeks (#2755, #2756).

Triage on 2026-10-03 covered all 299 open issues and 493 open PRs against current main. Each S1/S2 claim was checked with a code read or a local probe, and the evidence is recorded in `~/.capy/work/wave/triage-*.md`. 48 issues were already fixed on main and have been closed with evidence. About 190 open PRs are superseded or junk.

The previous two waves (#3013, #3014) fixed install/upgrade safety, worktree skill start, Codex model precedence and review gates. This wave targets what is left. The remaining severe bugs fall into four patterns:

1. **Silent loss.** gstack drops user data and reports success: transcripts never ingested, paid design variants overwritten, project state split across worktrees.
2. **False "all clear".** A check that did not run reports ready or pass: Codex reviews whose sandbox could not start, a retired Codex model, a design binary that dies on launch, search scripts that exit 0 when bun is missing.
3. **Non-Claude hosts half-work.** Codex and the other env-var hosts lose every `$GSTACK_*` path between shell calls, so skill-end, browse, design and state-root all break after the first block.
4. **Push blockers and platform gaps.** Redaction false positives block legitimate pushes, Windows /freeze denies every edit, and /ship stops in repos without a VERSION file.

### Release promises (the finish line)

The wave is done when each promise holds and is backed by a test that fails on main today:

- **P1. Nothing is silently lost.** A transcript, design variant or learning that gstack could not store is reported and retried, never marked done.
- **P2. No false all-clear.** Every gate that could not run says "not run" or "unavailable" with the reason, never "ready", "pass" or "no results".
- **P3. Every generated skill resolves its paths on every env-var host.** Every fenced bash block of every generated skill passes a fresh-shell conformance test on all 10 env-var hosts, and Codex (the one host we certify live) runs a multi-block skill end to end. Host tiers stay as declared in `scripts/host-config.ts` (Claude full, Codex experimental, others best-effort); this wave does not promise feature parity beyond paths, sections and discovery.
- **P4. Legitimate work is not blocked, and real secrets still are.** Known redaction false positives, Windows drive-letter paths and versionless repos stop blocking /ship, /freeze and pushes. Every redaction relaxation ships with true-positive controls that must still flag.
- **P5. Local control surfaces accept only gstack's own clients.** The browse terminal-agent socket rejects foreign extensions, a project's `.env` cannot loosen security settings, and navigation (including redirects) rejects link-local and metadata addresses (D0, D1, D2). Connection-time DNS rebinding is not covered by this release.

### Three invariants first (they turn the promises into enforced properties)

Most bugs in this plan are instances of three missing invariants. Build these first; the instance fixes then land against them.

- **INV-1. Gate outcome contract.** One typed outcome for every gate and outside review: `ran(findings) | not_run(reason) | unavailable(reason)`. "pass" requires positive evidence the check executed. All Codex invocation sites route through `lib/outside-review-result.ts`, which takes text, stderr and exit status (B1). A free lint fails on `2>/dev/null || exit 0` in `gstack-learnings-search` and `gstack-timeline-read`, and on calls to an explicit list of gate binaries wrapped in `|| true`; best-effort tails elsewhere carry a same-line reason.
  - **States.** `not_run` means gstack chose not to run the check (no plan bound, feature disabled, prerequisite missing on purpose). `unavailable` means it tried and could not (sandbox, retired model, binary died, bun missing, network). Every outcome this wave adds or changes maps to one state, a reason code and a fix action in a table in `docs/troubleshooting.md`.
  - **What users see.** Every outcome that is not `ran` prints one line: `<gate>: not run (<reason>). Fix: <command>` or `<gate>: unavailable (<reason>). Fix: <command>`, with the real values (exit code, path, host). Existing machine markers (`OUTSIDE_STATUS`, `CODEX_MODE`, `DESIGN_READY`) keep their names.
  - **What callers do.** A new `classifyOutsideReview({text, stderr, exit})` returns three separate fields: execution (`ran | unavailable(reason)`), findings (highest severity, or none), and verdict (`clean | findings | unverified | unavailable`); `validateOutsideReview` stays as a wrapper so the three direct importers in `claude-code/SKILL.md.tmpl:130,198,268` keep working. The two-argument CLI form keeps today's exit codes exactly (0 completed, 1 unavailable, 2 usage), because `lib/` runs live from the checkout and older rendered skills call it with `|| exit 1`. With `--verdict` (implied by `--stderr` or `--exit`) it prints `VERDICT: ...` and exits 0 / 3 / 4 / 1; every generated caller moves to that form in the same commit and branches on it explicitly. `unverified` covers a completed structured review with neither severity tags nor an explicit no-findings line (/codex review's existing UNVERIFIED state). /codex consult and challenge use a new `execution` gate that checks only execution evidence, not review markers. Reason codes live in `lib/gate-outcomes.ts`, imported by the validator and by the troubleshooting anchor test. A test runs an old rendered caller against the new lib. /ship and /review treat `unavailable` as missing coverage: they continue, show it in the readiness dashboard and the PR body, and never count it as a pass. A `findings` verdict with P0/P1 blocks exactly as a native P0/P1 does. Tested through the real CLI and the generated caller together.
- **INV-2. Write, verify, then stamp.** Storage marks work done only after confirming it landed: memory ingest (A1), design variant rounds (F4), learnings/question logs (G3). Staged, published and indexed are separate states.
- **INV-3. Host conformance test (free suite).** For every host with `usesEnvVars: true`, render all generated SKILL.md and section files, run `bash -n` on every fenced bash block, and execute each block's root-resolution lines in a fresh `env -i`-style shell against a temp install root with stub binaries. Fail on any empty expansion or a path starting with `/bin/`, `/browse`, `/design` or `/gstack-`; fail if any Codex SKILL.md is a symlink or any host SKILL.md exceeds 160,000 bytes. A generated-bash lint in the same suite fails on a `~/` path inside double quotes and on `mktemp` without a `${TMPDIR:-/tmp}` template. Both fail on origin/main today. Details: install-level checks extend the existing `test/host-conformance.test.ts` (codex, kiro, factory, opencode, cursor, copilot: no installed SKILL.md is a symlink, design/make-pdf dist present, every section pointer resolves to a readable file); render-level checks cover all 10 env-var hosts in one new test that renders once per host. Each fence that uses `GSTACK_*`, `$B` or `$D` must carry the shared prelude exactly once, and the prelude is executed under `env -i` and `set -u` with stub binaries, including the B/D consumers. Angle-bracket placeholders are normalized before `bash -n` (231 of 10,136 fences fail today only because of them). The lint tokenizes quotes and fails on: a `~/` word inside double quotes; `mktemp` with no template or a literal `/tmp/` template; `cd`, `rm -r*`, `mv` or `git -C` on a variable not assigned in the same fence unless written `cd -- "${VAR:?...}" || exit 1`. The lint and the size gate run on every host's render, Claude included. Sizes are UTF-8 bytes.

Main's count guard (`memory-ingest.ts:2507-2535`) counts gbrain's exit-0 "skipped" as landed, and gbrain stops printing per-file warnings after 5 per class, so stderr parsing alone is not enough. An unnamed failure refuses the whole batch. Remote-HTTP mode records "staged" rather than "ingested" (`memory-ingest.ts:2302`). A `--reconcile` pass (run once automatically after upgrade, then on demand) re-checks stamped entries and un-stamps pages absent from the brain so already-lost transcripts re-ingest. The upgrade migration only records that a reconcile is pending; the next ingest run does one bounded pass and prints the summary even under `--quiet`. Setup never calls gbrain for reconcile. Engineering contract: (1) a versioned state schema with an explicit transition table (`staged → imported_unverified → ingested`, plus `refused`, `quarantined`, `unrecoverable`), migrated from today's file; (2) the source fingerprint is captured from the exact bytes parsed, so a transcript that grows during import is not stamped as its newer self; (3) each entry records its gbrain `source_id` (`default` for entries stamped before this release), and the landing check and `--reconcile` query only the recorded source, so pre-wave pages are never re-ingested into new sources; (4) a lookup error or `pglite_busy` means "not yet checked", never absent; reconcile re-queues a page only when it is missing from its recorded source and the transcript file still exists, otherwise it counts it `unrecoverable`; (5) presence is checked with one `gbrain list` per source per run, content with `gbrain get <slug> --json` for at most 50 pages per run against a `gstack_content_sha256` frontmatter field gstack writes (gbrain stores its own hash), and pages over the cap are `imported_unverified` and never re-imported; (6) after 3 refused batches the batch is split in halves to find the bad page, which is quarantined with a reason printed even under `--quiet`; (7) one lock protects every writer (ingest, reconcile, migration flags) and a state-save failure fails the run; (8) this logic lives in a new `lib/memory-ingest-landing.ts` (ratchet new module, ≤800 lines). Capability facts: gbrain installs at latest HEAD (floor 0.20.0); `import --json` reports `failures` from 0.48.5.0 and `source_id` from 0.50.1.0; managed-import `Pending:` receipts count as unchanged, so the landing check is needed even with `failures`; capability is detected by behavior.
