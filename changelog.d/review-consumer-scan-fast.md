**/ship's review plan finishes on results repositories with large trial files.** The scan that decides whether a changed data file is read by code ran `git grep -o` with every data file name, and git's -o retries every name after each match: on harness-evals #551 (304,000 files, 16 MB trials files naming about 80 data files) one file took 220 s and the plan ran out of time at 1,703 s even with a 30-minute limit. The scan now lists the files that can hold a name once per scan, finds the ones that do with `git grep -l` over a scratch index, and picks their matches itself the way -o does, so its results are byte-identical; on #551's tree the whole scan takes about 40 s on a 4-core machine instead of running past its 120 s deadline. docs/review-policy.md.
