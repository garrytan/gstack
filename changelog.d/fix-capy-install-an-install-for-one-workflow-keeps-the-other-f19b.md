- **Installing gstack for one workflow no longer drops another workflow's install check on the same machine (#3561).** When /ship's docs step runs `gstack-capy-install --for document-release` on a machine already installed `--for ship`, an ok run at the same checkout, HEAD and Bun now keeps what the earlier run certified: the verdict's required components become the union and `for=` lists both workflows (`for=ship,document-release`). Each workflow install also writes its own record at `<verdict>.for/<workflow>.json`, so a child install that resolves another Bun, or fails, no longer leaves /ship refused with `INSTALL_UNVERIFIED` mid-run. A new HEAD still replaces both.
