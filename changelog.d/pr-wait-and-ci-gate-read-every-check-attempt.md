- **`gstack-pr-wait`, `gstack-ci-gate` and the release cut no longer call a commit green while a check on it failed.** They read CI from GitHub's rollup or its default check-runs list, which hold only each check suite's latest attempt, so when a rerun attempt created no jobs the failed run before it disappeared, and a workflow run that failed before creating any job never appeared at all. That is the false green the merge queue had on gstack-evals#303 (#4235). All three now also read CI at the commit through the merge queue's own helper, which reads every attempt and every workflow run, and keep the worse answer per check. So `gstack-pr-wait --until green` blocks with `check failed: checks` and `check failed: sealed (run <id>, no jobs)`, the land gate says `VERDICT FAIL`, and the release cut skips the commit. The release cut now also counts a failed commit status as red, as the merge queue does. A rerun that passed still reads green, and an unreadable read is an error, never a pass (GST-2252).
