- **/ship can now review results PRs that publish raw session data.** A repo's ship policy can list folders under a new key, `review_content_patterns`, next to `review_exclude_paths`. A file both keys match counts as data whatever its name, so /ship's reviewers leave it out, the same way they already leave out JSON, CSV, logs and images. Source files in that folder (`.ts`, `.py`, `.sh` and the like, in any letter case) still get reviewed. Before this, files such as `.patch` diffs, a `MANIFEST.sha256` and licence texts with no extension always counted as code, so a folder of them could never be left out, and a PR like gstack-evals #352 (13.8 MB, of which 13.6 MB is published session data) could not get under /ship's 2 MB review limit. Nothing is guessed: only a pattern on the base branch counts, a content pattern on its own excludes nothing, and the secrets scan and the sealed-output guard still read every excluded file. Details: docs/ship-policy.md#review-content-patterns.

  **Also fixed:** when a `review_exclude_paths` pattern kept too many files for the reviewers' read command (more than 24,000 bytes of file names), /ship quietly dropped the whole pattern and sent the folder to the reviewers anyway. It now stops before review with `REVIEW_EXCLUDE_KEEP_TOO_LARGE`, naming the pattern, how many files it keeps and why, and the fix (docs/troubleshooting.md#review-exclude-keep-too-large).
