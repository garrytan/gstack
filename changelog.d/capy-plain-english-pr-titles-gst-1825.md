- **/ship now writes pull request titles, commit messages, branch names and changelog entries that say in everyday words what changed for someone using the project.** An issue code may follow at the end, as in "Stop gstack from hitting GitHub's rate limit while it waits on PRs (GST-1713)", but the front of a title stays plain: no `type(scope):` prefix, no tracker codes and none of the repository's own coined terms. The new `gstack-plain-title` command checks titles, branch names, PR openings and changelog entries against a word list a repository keeps in `.gstack/plain-titles.json`; a repository without that file gets warnings, never a refusal. /ship and `gstack-post` refuse to post a title that fails, and a "Plain title" check on every new pull request does the same for PRs opened any other way. Pull requests opened before the rule started are exempt.
- **PR bodies now open with one or two plain sentences and end with one collapsed "Agent notes" section.** The ship receipt, approval and plan lines, issue codes and review bookkeeping that gstack's merge tools read now live in that section instead of a JSON block at the top of the body. The merge tools read it there and still accept the older layout, so open pull requests keep working. When gstack merges a pull request, main's commit title is the pull request's checked title.
- **The README now lists what gstack is for**, and /ship's PR opening names the goal a change serves.
