- **A receipt carry no longer lets a removed or rewritten test assertion merge unread.** `gstack-ship-receipt carry` used to treat every edit under `test/` as harmless, so a lane whose test went red after /ship could loosen the assertion (`expect(a).toBe(1)` to `expect(typeof a).toBe('number')`), carry the receipt as a "test-only change" and land with no reviewer reading it. Now a carry whose test diff removes or changes an assertion line (an `expect`, `assert` or matcher, or a `test(...)`/`it(...)` line) refuses with `RECEIPT_CARRY_TEST_WEAKENED`, naming each hunk as `path:line`, and carries only after one scoped fix-check reads the packet it writes (`carry --test-review <record.json>`, bound to the packet's sha256). New tests and assertions still carry, and a skipped or deleted test still refuses through the review depth. The check reads removed or rewritten assertion lines only, so a value changed inside a multi-line matcher, an added early return, or a golden or snapshot edit still carries as test-only. `test/land-merged-checks.txt`, the list land runs on a moved base, the touchfile maps that select tests, the paid-eval policy and budget data and the ratchet allowlists are now product for a carry, so editing them can't ride a test-only carry either, including on a retargeted stacked PR (GST-2204).
