### Fixed

- **An outside review that says it could not verify the change is no longer read as a pass (#3925).** `lib/outside-review-result.ts` printed `VERDICT: clean` / `FINDINGS: none` for a Codex reply ending `Verdict: Can't verify (one changed file excluded and four required suites blocked)`. Now the reply's last verdict has to approve the change (`ready`, `LGTM`, `approve`, `ship it`, `pass`, `clean`, `good to go`) or say `not ready`, which still blocks. Anything else, or an approval that says something was excluded, blocked, skipped, not run or could not be verified, is `VERDICT: unverified` with the new `REASON: unverified_verdict` and exit 4. A quoted verdict, an `Overall verdict` line, a dash separator and a `Verdict` heading with the value on the next line are all read. See docs/troubleshooting.md#outside-review-unverified-verdict.
- **A numbered finding without a P0-P3 tag is no longer dropped (#3925).** A reply with `1. **Nonblocking — x**`, `Verdict: ready` and `END OF REPORT: 1 findings (0 blocking)` printed `FINDINGS: none`. In a reply with a verdict line that doesn't conclude it found nothing, every numbered item is now counted as a finding, and one with no readable severity makes `FINDINGS:` print `unspecified`, in the helper and in `gstack-outside-voice run`. The verdict is unchanged (`clean` here, since the reviewer approved). A consult answer with no verdict line, and a real clean reply, still read `clean` / `none`.
