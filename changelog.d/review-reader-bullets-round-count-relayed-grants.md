**/ship no longer stalls on review notes a reviewer already cleared, counts review rounds the way the review policy reads them, and keeps security findings out of the PR body.** When a reviewer reports no blocking findings, its summary bullets such as "noted P2 findings", "deferred P1" or "P0 or P1" become notes the lead lowers with a reason, instead of blockers with no way to clear them. A fix-check, the scoped re-read after the one fix round, no longer counts as a review round in the review loop, the PR history or the receipt. A round grant the owner gave in a message while a /ship run was stopped can be recorded with `gstack-approvals round-grant --owner-ref <thread>:<message>`, which marks it as relayed. The receipt's list of round grants now shows a security finding as its ruled public form, or as an opaque id when it has no ruling, with the grant's reason recorded privately in that case, so posting the PR body no longer stops on a finding the owner had already ruled not security class.
