- **`/health` and every check that picks gbrain's health probe now look for gbrain's config under `GBRAIN_HOME`, and gstack trims `GBRAIN_HOME` exactly as gbrain does.** The health selection in `lib/checks.ts` read only `~/.gbrain/config.json`, so on a machine where `GBRAIN_HOME` names the brain (gbrain's usual unattended setup) it judged a different brain's config: it could skip the gbrain check for the brain gbrain actually uses, or run it because of an unrelated `~/.gbrain`. It now uses the same rule as gbrain's own `configDir()`: `GBRAIN_HOME` trimmed with JavaScript `trim()`, with `.gbrain` appended, else `~/.gbrain`; a `GBRAIN_HOME` gbrain would refuse (relative, or with a `..` segment) selects nothing instead of falling back to `~/.gbrain`. gstack's TypeScript gbrain helpers (`gbrainConfigDir()`, which seeds gbrain's database URL for every gbrain call gstack makes) now trim and refuse the same way, and the shell helper `bin/gstack-gbrain-home.sh` now treats a `GBRAIN_HOME` made only of Unicode spaces such as a no-break space or a byte-order mark as blank, as gbrain does, instead of refusing it. Nothing changes when `GBRAIN_HOME` is unset.
