- **`ready` binds a receipt with an older review_exclude digest when the policy change touches none of the PR's files.** After a `review_exclude_paths` edit landed on main, `gstack-ship-queue ready` refused every receipt that had recorded the old digest, even when no file the PR changed fell under any pattern (harness-evals #274 and #276 after policy PR #278). The queue now uses carry's rule. When neither the receipt's recorded selection nor HEAD's holds a file the PR changed, the receipt binds. A selection that holds a PR file, excluded or kept, and an unreadable base policy still refuse. (GST-1434)
- **The review_exclude name scan no longer times out on large results repos.** The scan that keeps a file a program names by full path ran one `git grep` over the whole tree, so on harness-evals #269 it searched 30 MB of receipts for 4,354 candidate paths, ran 278 s past its 120 s limit and kept every file. It now greps only the code and test files that can name a candidate, so its cost follows the code, not the data the PR adds. A git failure or timeout still keeps every candidate. (GST-1435)
