The docs link check and `gstack-prose-lint` read code fences the way CommonMark does. A line that opens with an inline code span, such as ````` ````gstack-ship-receipt```` ````` in `docs/troubleshooting.md`, no longer opens a fence. Before, `scripts/check-doc-links.ts` and the docs lane's pregate refused valid links to headings and `<a id>` anchors after such a line (six links on main, such as `troubleshooting.md#unattended-runs-and-artifacts`). `gstack-prose-lint`, which /ship runs with `--gate` on the lines a branch adds, read the lines after it as code and stopped at a later fence it took for unclosed, so it reported 23 of the 72 findings in that file and passed a sentence added in its second half that it flags in its first. The link check also ends a block only on a bare fence at least as long as the one that opened it. Contributed by @Davmunrey.
