The docs link check reads code fences the way CommonMark does. A line that opens with an inline code span, such as ````` ````gstack-ship-receipt```` ````` in `docs/troubleshooting.md`, no longer opens a fence, and a block ends only on a bare fence at least as long as the one that opened it. Before, `scripts/check-doc-links.ts` and the docs lane's pregate refused valid links to headings and `<a id>` anchors after such a line (six links on main, such as `troubleshooting.md#unattended-runs-and-artifacts`) and skipped the links on those lines.
