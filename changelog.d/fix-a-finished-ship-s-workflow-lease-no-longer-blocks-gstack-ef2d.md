- **A finished /ship no longer holds back a gstack upgrade.** Each workflow now records its run on the shared installation's lease when it starts and closes that run when it ends, so `gstack-upgrade` and the session-start upgrade stop waiting on a run that already finished. A run still open on the same holder keeps blocking, an unfinished run stops counting 120 minutes after it started, and `bin/gstack-lease list` shows a lease whose runs have all ended as `idle`. `gstack-lease open --run <id>` now answers whether one run is still open, which the /ship preflight and the gate-disposition check rely on.
