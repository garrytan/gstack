- **The destructive-command check stops asking about harmless work in `/tmp` and in written deploy hooks, and closes the last quote tricks around disk wipes.** A relative `rm -rf` after a second `cd` inside `/tmp`, inside a subshell, loop or `if` body entered from `/tmp`, or through a `for` loop variable over plain names no longer asks, and neither does `rm -rf "/tmp/a b"` or a `cd` into a variable the same command sets to a `/tmp` path. A `git checkout -f` or `reset --hard` written into a file with `cat > hook <<EOF` is data and no longer asks until the command runs that file or pushes to the hook's repository, and a `reset --hard` after a `cd` probes the folder the `cd` leads to when it already exists. `wipefs -a` is now blocked on every target, image files included, a redirect into a disk is blocked when its path is quoted (`>'/dev'/sdb`) or goes through a folder that links to `/dev`, and a quoted `#` no longer hides the rest of a command. SQL `TRUNCATE` text in a grep or echo asks again when it is piped to a shell, run through `$( )`, `<( )` or `git grep -O`, and stops asking when only a later, separate statement has a pipe. `git push -fn --no-dry-run` is read as a real force-push, and `echo wipefs-archive` is no longer blocked.
