- **/ship no longer counts a reviewer's "nothing blocks" summary as a blocking finding.** The adversarial reader often opens with a verdict like "I found nothing that blocks. There are three Low findings, all FIXABLE." The review ledger only recognised a few spellings of "nothing blocks" and only when the line named no severity, so this line was collected as a CRITICAL finding, lead judgment couldn't lower it, and the receipt reported `blocking_found=1` when nothing blocked. The ledger now reads the common ways of saying nothing blocks ("nothing that blocks", "nothing blocking", "none of which would block", "no blockers") and collects such a line at the most severe severity it counts (Low here), never as CRITICAL, on every review class. It stays strict: the line is read as a verdict only when every sentence on it is the verdict itself (the "nothing blocks" clause, a count like "three Low findings", a tag like "all FIXABLE", or a trailing "and none can change outcomes"). A line that also names a defect, adds an exception ("nothing blocks except the token leak", "with one exception", "however", "though"), hedges ("probably nothing blocks"), says something does block, names a file and line, carries its own Severity or Blocks field, or continues the line above still collects as CRITICAL, and the real findings below the summary collect exactly as before.
