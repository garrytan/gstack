### Fixed

- **`gstack-brain-sync` no longer reports a rejected push as an auth error when the remote's URL or path happens to contain `auth`, `permission`, `401`, `403` or `forbidden`.** It searched git's whole error text, including the `To <url>` line and the quoted URL, so a remote such as `github.com/author/notes` or a path under `/tmp/x403y` skipped the fetch-and-merge retry, and the sync stayed `push_failed` until someone pushed by hand. The check now ignores the URL. A real auth refusal (for example `The requested URL returned error: 403`) is still reported as one. In CI, the free shard's temporary folder name turned eight brain-sync tests red at once (Free Tests 41847262176).
- **The browse daemon picks its port after Chromium has launched, right before it binds.** It used to check a random port first and bind it only after the browser launch, which takes seconds. Under load another process could take the port in that time, and the daemon failed with "Failed to start server. Is port … in use?" (Free Tests 41951644962).
- **`test/gate-reuse.test.ts`**: the fixture's bare origin turns off auto-maintenance, as the pregate fixture already does. Each push started a detached `git maintenance run --auto` that could remove an object folder while a later push was writing into it (Free Tests 41980850843).
- **Paid evals**: the ship doc-sync interface now says how to create the private folder it allows (one `mkdir` as its own call), after two `ship-docsync-store` runs each joined a no-op mkdir stand-in to a read line (41850017482, 41987975678). The coverage-audit prompt asks for the two file reads after the skill files, so the skill's dedicated-read step is seen before the files are read (`plan-eng-coverage-audit`, 41932813292). The QA-only cleanup names the terminal record, port file, daemon and daemon-log state when it can't confirm the terminal's identity (`qa-only-no-fix`, 41962523474).
