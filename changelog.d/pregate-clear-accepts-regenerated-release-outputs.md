- **`gstack-pregate clear --receipt` accepts a remote gate run from before a merged release when the release only regenerated a declared release output.** A PR that merged a release commit was refused because a generated file the policy lists in `release_outputs` was checked against the `stamp_files` list first, and `clear` never reran the release tool the way the tree receipt does. A `release_outputs` path is now judged by the release-output rule, and with `--allow-repo-commands` `clear` reruns `release_tool` on the head and accepts an output it regenerates byte for byte. Without the flag the receipt is refused as before, and the refusal now says to pass it. A hand edit to the generated file, or any path outside `release_outputs`, is still refused.
