**A results PR whose `pins.sha256` lists its data now gets `review_exclude_paths`, and large data PRs can raise the consumer-scan cap.** On harness-evals #538 the exclusion kept all 2,140 matched receipts in review and /ship refused a 13.3 MB diff: the name scan ran `git grep -o` with 2,140 paths, which ran past its 120-second bound, and even a finished scan would have counted the hash manifest that lists them as code. The scan now lists matching files with `git grep -l` and reads each one (the #538 plan took 48 s instead of 163 s and left all 2,140 out), and a hash or pin manifest (every line a hex digest and a path) keeps nothing and no longer reads as money, auth or data for review depth; a manifest with any other line is read as before, and its lines still count for secrets. `GSTACK_REVIEW_CONSUMER_SCAN_CAP` raises the 2,000-file consumer-scan cap, and a tripped cap prints a `CONSUMER_SCAN:` line naming both remedies. docs/ship-policy.md#review-exclude-paths, docs/review-policy.md.
