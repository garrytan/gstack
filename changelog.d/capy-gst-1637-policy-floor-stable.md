- **A ship-policy floor above the newest stable gstack release is refused by name, and the doctor stops sending sessions into a fix that cannot work.** `gstack-ship-policy validate`, and the new pregate `policy-floor` check on a branch that changes `.gstack/ship-policy.json`, refuse a `min_gstack_version` above the newest stable gstack release (`POLICY_FLOOR_ABOVE_STABLE`, naming the floor and the release), because every stable-channel lane would refuse that policy and no upgrade could clear it. The release is the highest `v<version>` tag gstack's origin lists, else the local stable ref and release tags; when none resolves, both warn (`STABLE_RELEASE_UNKNOWN`) and say the floor was not compared. The doctor's `floor` row now compares the version the checkout reads policies as (`runningGstackVersion`, as `validatePolicy` does), so an unstamped main checkout that already reads the floor's keys passes instead of warning forever, and when no stable release meets the floor it says `no release meets this floor yet` and offers no fast-forward; the trailer note becomes `floor=<f> (<file>; no release meets this floor yet)` with no `fix:`. The gstack skill now runs a floor fix once and reports a floor no release meets instead of rerunning the install before every workflow. (GST-1637)
