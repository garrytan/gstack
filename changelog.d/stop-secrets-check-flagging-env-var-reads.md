- **The preflight secrets check no longer fails a branch for code that reads an environment variable, or for a self-describing fixture label in a test file.** `env.kv` already let `process.env.X` through, but `token = opts?.env?.AGENT_API_TOKEN;`, `ctx.env.X`, `import.meta.env.X`, `process.env["X"]` and `System.getenv("X")` read as credential values and failed `gstack-pregate` (yc-software/qm, GST-1894). An `env` member of any object read by an ALL-CAPS name, and an indexed or call read whose argument is a quoted ALL-CAPS name, are now code. In `*.test.*`, `*.spec.*`, `test_*.py` and `*_test.*` files only, a value made only of lowercase words with a credential word among them (`"personal-secret"`, `"staging-api-key"`) is a fixture label. A literal after the read (`?? "<secret>"`, `os.getenv("X", "<secret>")`), including one in backticks or wrapped onto the next line, a literal used as the variable name when it isn't ALL-CAPS, the same label outside a test file, and every known key prefix still fail. An ALL-CAPS literal used as the variable name still passes, as it did before, because it reads like a variable name. `os.environ["<secret>"]` used to pass because the check skipped the quote the match had taken; it now fails.
