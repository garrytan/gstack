**`/gstack-ship` now reviews a diff over the 2 MB review ceiling in slices instead of stopping.** When one reviewer's kept diff is bigger than 2,000,000 bytes, `gstack-review-dispatch pass` splits it into up to 8 slice readers that share no file and together cover every file, keeping each top-level folder in one slice when it fits. Git checks that coverage before any brief is written, and `gstack-review-dispatch verify` checks it again at the reviewed tree, refusing a missing, uncollected, overlapping or dropping slice. A sliced reader is still one reviewer for round counting. One file over 2 MB by itself, a diff that needs more than 8 slices, or a slice that would name more paths than one command can carry still stops with `REVIEW_DIFF_TOO_LARGE`, now naming the reason. Large results PRs and large pure-deletion PRs whose files sit in a few folders or subfolders can now be reviewed in full; a single flat folder of thousands of small files can still hit the path limit. Diffs under the ceiling are reviewed exactly as before.
