**`gstack-ship-queue land --pin` tests the merged tree when a PR's base moved after its CI (GST-1316).** Under `merge: direct`, land checked the PR's own green checks, but those ran on the PR before newer commits reached main. #3886 was green on its own, landed onto a newer main, and pushed `ship/DRIVER.md` to 12,329 bytes against its 12,288-byte cap, so Free Tests on main went red.

### Added
- **`land` policy key:** `land.merged_checks` lists the commands land runs on the pin merged onto main's tip, in a throwaway worktree, when the base moved past the pin's merge base. Land merges only when every command passes, and prints `MERGED_CHECKS: pass tree=… base=… pin=… checks: …`. A failure refuses with the new `QUEUE_LAND_MERGED_CHECKS`, a conflict with `QUEUE_LAND_NOT_CLEAN`, and nothing merges. Without the key, a stale base refuses with the new `QUEUE_LAND_STALE_BASE`. A lane no longer has to merge main, rerun CI and re-ship each time another PR lands first. gstack's own policy adopts the key once a release carries it.

### Fixed
- **`gstack-ship-queue land --pin`:** after the merge, land checks that GitHub merged onto the base it checked or one the pin contains. If main moved in between, it reruns `land.merged_checks` on the landed tree and reports `QUEUE_LAND_UNVERIFIED` with no land note when they fail or the key is absent.
- **Docs:** `docs/ship-policy.md#land-direct` describes the merged-tree check and the `land` key. The release section now says a release may not delete a release output, and that a rerun after GitHub merged a release fetches the pin, then reads its parent, with an unreadable parent refused as `QUEUE_NOT_READY`. `docs/troubleshooting.md` and the `docs/captain.md` refusal table cover the new codes.

### Tests
- `test/ship-queue-land-direct.test.ts`: on a stale base, a pin whose merged tree breaks a stand-in budget check is refused with `QUEUE_LAND_MERGED_CHECKS` (also under `--dry-run`) and main stays put; a pin that passes lands with main's tree equal to the checked merged tree, and a rerun checks again. A stale base with no `land.merged_checks` refuses with `QUEUE_LAND_STALE_BASE`, and a conflicting pin with `QUEUE_LAND_NOT_CLEAN`. The key's validation is covered. The mid-land race test still expects `QUEUE_LAND_UNVERIFIED` with no land note.
