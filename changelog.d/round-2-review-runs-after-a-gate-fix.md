- **A second review round no longer reports done when nothing was reviewed.** After the first review pass, a fix that touched a gate-class path (CI, auth, merge checks) was planned as "the step applied no edits" unless another fix flag came with it, so /ship's round 2 printed done and no reviewer read the fix. That fix now gets its full review pass on the changed range. When the plan is told nothing was fixed but the branch has new commits since the reviewed head, it now refuses with `review_required_no_readers` instead of printing done. `gstack-review-dispatch` also stops reading its own flags out of the review-plan flags after `--`, so a plan's `--pass 1` can no longer stand in for the pass id.
