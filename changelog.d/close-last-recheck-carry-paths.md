- **A pull request's merge head can no longer keep its `/ship` receipt without a full review.** Three gaps let a receipt through on less than the full review R51 asks for. A head whose own added lines match the reviewed ones but whose removed lines changed with the base (the base took `SAVE_VERSION := 83` under a branch reviewed as `82` to `84`) used to carry after one scoped reader; it's now a product change, so carry refuses and `/ship` reviews the head in full. A receipt an older gstack carried through a scoped re-check no longer carries on through a later base merge or stamp, and `gstack-ship-queue` won't bind it (`QUEUE_RECEIPT_STALE`), until a fresh full review replaces it. And a `/ship` body post keeps the PR body's `gstack-receipt-runs` block, so `gstack-ship-receipt history` counts every run instead of only the last. The read-only review's `PR_ROUND_CAP` stop no longer offers a round grant it can't honor, and the `stamp-only-carry` no-stop class is gone: a refused carry already runs Steps 2-16 without a stop, so a receipt that still lists that class is invalid and its PR runs `/ship` again. See docs/review-policy.md#rounds-per-pull-request.
