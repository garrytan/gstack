**The destructive-command check catches more force pushes and outside deletes, and stops asking about a few harmless spellings.** A force push to main is no longer read as a dry run when `--no-dry-run` is abbreviated (`git push -fn --no-dry origin main`), when the `-n` is really the value of `-o`/`--push-option` (`git push -f -o -n origin main`, also with `--push`), or when `-f` sits in a group with a digit (`-f4`, `-4f`, `-fo-n`). A push-option value is no longer read as the remote, so `git push -f -o ci.skip origin` on main is blocked like `git push -f origin`. A relative delete after `cd` into a system folder (`cd /etc/nginx && rm -f sites-enabled/default`, also `cd ../../etc`) and removing a device node under `/dev` (`rm -f /dev/loop0`, `/dev/sg0`, `/dev/zram0`) now ask, like their absolute-path forms. A push-option value never makes a push safer. It can't turn a push into a dry run, and a `--no-dry-run` after `-o` still undoes `-n`. Quoting no longer changes the decision: `rm -rf "/home/me/app/dist"` is allowed like `rm -rf /home/me/app/dist` (#4628), and the quoted title or body of `gh issue` or `gh pr` create, comment and edit is read as text, like its backslashed spelling (#4601).
