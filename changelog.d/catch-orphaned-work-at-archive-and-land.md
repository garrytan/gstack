- **A Captain can no longer archive a thread that still holds an open PR, and a landed PR's issue closes in the same step.** The new `gstack-archive-check thread` runs right before a Captain archives a crew thread. The Captain hands it the thread and issue lists it read from Capy, and it re-reads every PR the thread holds from GitHub. It refuses while any of those PRs is open (a successor does not change that) or while an issue in a working state is still assigned to the thread. It also refuses when a read is stale, truncated, unparsable or failed. Every run prints a handoff stub (each open PR's branch, head commit and CI state at that head, plus the open issues) for the next thread's brief. `gstack-archive-check landed --pr <n>` runs after `gstack-ship-queue land` and names the tracker code in the merged PR's title, so the Captain closes that issue in the same program, but only when the issue links this PR, no other open PR and no open sub-issues. crew/docs/captain.md (No orphaned work, Direct land), the gstack factory page, /captain and the /runaway-stopper rotation steps now say a thread with an open PR stays until that PR merges or closes.
