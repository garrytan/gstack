- **A cleared remote gate now satisfies a /ship lane whose inventory refuses its own tree.** gbrain's lane inventory refuses, on purpose, any tree that changes its CI-reuse files, so `gstack-ship-release accept` stopped with `CI_CARRY: none label=unit (inventory_failed: …)` even after `gstack-pregate --remote` had cleared the identical tree, and every such PR needed `--no-lanes-approved` plus a manual approval (GBRA-345). Now, when the carry refuses as `inventory_failed` and `.gstack/tmp/pregate.json` verifies for HEAD's exact tree with the remote gate's own report for that tree (tests above 0, not a stamp-only substitution), that receipt satisfies the lane: accept prints `CI_CARRY: remote_gate label=<lane> receipt=…` naming the substitution and records the lane as `source=remote_gate` in the evidence ledger. A gate cleared for any other tree, or a receipt naming another tree, still stops, with a `CARRY_DIAGNOSIS:` line saying why. A CI run whose `tree.json` lists no files (a rerun of only the failed jobs) now says to dispatch a fresh full run instead of a bare `no_tests`. (GST-1688)
