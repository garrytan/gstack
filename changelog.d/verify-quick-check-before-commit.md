- **When Claude Code runs /verify right before a commit, it now gets a quick check instead of the full fix loop (GST-3150).** Claude Code 2.1.286 and later tell the model to run any skill named `verify` before every commit that isn't docs-only or tests-only, so gstack's /verify was starting its whole build-and-fix workflow, first-run notices included, on ordinary commits. Now that call runs one command, `gstack-checks quick`: the repo's existing checks (typecheck, lint) and the tests /ship would pick for the change, with no code edits, no new tests and no questions, ending in one line: `VERIFY PASS`, `VERIFY FAIL`, or `VERIFY skipped: <reason>`. A repo with no `origin` remote, check commands you haven't approved yet (type /verify once in that repo to review and approve them), or nothing to run is skipped and the commit goes ahead; a failure makes the model stop and ask you before committing. Typing /verify yourself still runs the full skill. To turn the pre-commit check off, run `gstack-config set verify_before_commit off`; to stop Claude Code from asking for it at all, install with `./setup --prefix`, which names the skill /gstack-verify.
