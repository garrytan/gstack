- **`gstack-uninstall` no longer deletes your repo's committed `.gstack/` files or unsaved work in `.gstack-worktrees/`.** Run from inside a repo, uninstall used to delete the whole `.gstack/` folder and every `.gstack-worktrees/` checkout, even with `--keep-state`, so a committed `.gstack/ship-policy.json` showed up as deleted in `git status` and a worktree's uncommitted files were gone. Now `--keep-state` keeps both folders. A plain uninstall still clears gstack's own ignored browse state, but keeps every git-tracked file under `.gstack/` (and says so), and it stops with exit 2 before removing anything when a checkout there has uncommitted changes (even with `status.showUntrackedFiles=no`), holds commits no branch or tag contains, or isn't a worktree this repo registered (as after moving the repo, or a separate clone put there, which uninstall never opens with git), naming the worktree and the fix: commit to a branch or stash, re-run with `--keep-state`, or pass the new `--force-worktrees` to delete them anyway. A symlinked `.gstack-worktrees` is only unlinked, as before, and never followed, so the checkouts it points at are kept. A worktree nested inside another checkout under `.gstack-worktrees/` is not checked yet and is still deleted with its parent, as before. The checkouts it removes also leave `git worktree list`; the registrations of your other worktrees are never touched, even when their folder is missing for now (GSTA-461, GST-2197).
