**A base branch whose `review_exclude_paths` list breaks the policy schema no longer stops every /ship.** When the only errors in the base's `.gstack/ship-policy.json` are in `review_exclude_paths` or `review_content_patterns` (such as 65 patterns, past the limit of 64), `gstack-review-plan` sets both keys aside and reviews every file, applies every other key as committed, and prints `REVIEW_EXCLUDE: fallback (WARNING: …)` with each error and the fix; the ship receipt records it as `review_exclude_fallback`, and every other step that reads the base policy reads it the same way, so the PR that corrects the list can be reviewed and land; `gstack-ship-policy validate` still reports the list as invalid. Before, every plan on that repository refused with `POLICY_INVALID`, the fixing PR's included. Any other invalid key still stops the plan, and a branch's own policy still never counts before it lands. (GST-3399)
