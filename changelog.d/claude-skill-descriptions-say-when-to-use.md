- **Claude Code's skill list now says when to use each gstack skill, so Opus loads /review and /plan-eng-review when a request fits.** gstack cut every Claude Code description to its first sentence, which says what a skill is but usually not when to load it. In a test with Opus 5.5 in Claude Code, "Review my changes before I land them" loaded /review 0 of 3 times (its line read "Use when you review this PR's diff."), and "plan this feature" loaded no gstack skill in 9 tries. Almost every Claude Code description now keeps a short when-to-use clause after its first sentence. The clause is the skill's own trigger phrases ("Use for: review my changes, look over my diff, review this pr."), or its "Use when" sentence when it has no trigger list; /design-consultation and /eval-plan keep only their first sentence. /review's line no longer assumes a PR exists (local changes and a branch count), /plan-eng-review says it plans a feature before you build it, and the `gstack` router's line says what it does instead of "Router for the gstack skill suite." The skill list Claude Code loads every session grows by about 840 tokens. The clause is added only to Claude Code's trimmed list, so `--catalog-mode=full` and the other hosts don't get it.
