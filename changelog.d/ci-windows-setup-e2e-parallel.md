**Windows Setup E2E finishes sooner on install changes.** Its two long jobs ran every case one after another, so a pull request that touched an install file waited about 8 minutes for the slower one. The false-positive recovery and the two forced-CSO-failure cases now run on their own Windows runners beside the setup case, and the held-install journey splits into three jobs (clean and already-unmerged, dirty then trial and go-back, dirty then a later release), each building the same fixture from `scripts/windows-held-install-fixture.sh`. Every case still runs on every in-scope pull request, and each job checks that its own cases ran.
