- **When the project owner rules that a review finding can ship as a disclosed note, /ship now honors that ruling on a second full review pass and on the cross-model review step, as the review policy already promised.** Before, only the narrow re-check after a fix read the owner's rulings, so a pass held open by one ruled finding stayed unverified, and a cross-model finding that no row recorded was counted as unrecorded (garrytan/gstack#4248, #4266, #4257). Now `gstack-review-read` applies each approved ruling whose head lies inside the range a review row covered, and `gstack-review-scope summary` counts a ruled finding as noted only when the run's newest review row accepts that ruling. A ruling names a finding by its fingerprint or by its pass-qualified ledger id, never by a bare id that repeats in every pass. The existing limits still hold. A ruling outside the reviewed range closes nothing, the lane's own row fields rule nothing, gate findings are never ruled, and an edit after the bound head still needs review. A review that stopped partway binds only if its commit didn't move while it ran, so a read that left a commit and came back to it no longer counts as one tree. On the re-check after a fix, a finding it saw as fixed no longer holds the row open, and the refusal now names the findings no ruling can close. Approval reads include the mounted Capy Drive mirror in every shell, so rulings look the same everywhere.
