- **A /ship run that audits its docs twice keeps the review it already has.** When Step 14.5 ran again after a base merge and restamp, `gstack-ship-receipt write` reset only the last audit's files, so a file the first audit edited and committed stayed in the `review_exclude_paths` selection and write refused the reviewed digest (gbrain #8678); the only way out was HEAD's digest, which skips review of the delta. Each docs snapshot now names its /ship run (`--run`), each post snapshot records the files its audit edited (`--pre <Prepare snapshot>`), and a re-audit's post snapshot carries the earlier audit (`--carry`). Write resets every file this run's audits edited to its content before them and binds the reviewed digest. A file no audit edited, an edit after an audit, and a carried audit from another run still refuse. (GST-1616)
