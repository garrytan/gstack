- **Posting a PR description no longer stops on the CI run numbers /ship records in it.** The JSON summary /ship writes into a PR description lists each GitHub Actions run it reused, and `gstack-post` read those 11-digit run numbers as phone numbers, so every post with reused CI asked for `--confirm`. A run number now passes when it sits in one of the summary's run-number fields (`ci_carried[].run`, `flaky_exception[].runs`, `issues.flakes[].run`) and the block is exactly what /ship's writer renders: closed, valid against its schema and byte-identical to its own rendering. The same number in prose, next to the block, under any other key, or inside a hand-written or broken block still needs confirmation.
- **`gstack-approvals import` records plans whose autoplan run id looks like a phone or card number.** A run id such as `HARN-64-20261109177601` ends in a 14-digit time stamp, and the scanner could read it, alone or with the digits before it, as a phone or card number, so import refused the approval. Import now skips those two findings only where it places the run id itself, and only for an id of the minted `<name>-<14 digits>` shape. A phone number in the same approval's words or plan title, or the same id typed into `gstack-approvals add`, still refuses.
