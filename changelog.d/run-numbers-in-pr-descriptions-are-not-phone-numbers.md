- **Fewer false privacy holds when posting PR descriptions and running the pre-merge checks.** Three kinds of machine-written numbers no longer read as personal data. GitHub Actions run numbers in the JSON summary /ship writes into a PR description (`ci_carried[].run`, `flaky_exception[].runs`, `issues.flakes[].run`) no longer count as phone numbers, so a post with reused CI no longer asks for `--confirm` once per run; only a block exactly as /ship's writer renders it qualifies, and the same number in prose, next to the block, under any other key, in one of those fields holding anything but an 11-to-20-digit run number, or inside a hand-written or broken block still needs confirmation. A four-part version written to or read from a `VERSION` file, or set right beside a three-part version (`path.join(dir, "VERSION"), "1.98.0.0\n"`, `v1.97.2 to 1.98.0.0`), and a `VERSION` file holding only the version, no longer count as public IP addresses; a public IP with no version beside it still reports.
- **`gstack-approvals import` records plans whose autoplan run id looks like a phone or card number.** A run id such as `HARN-64-20261109177601` ends in a 14-digit time stamp, and the scanner could read it, alone or with the digits before it, as a phone or card number, so import refused the approval. Import now skips those two findings only in the time stamp (and the thread number right before it) where it places the run id itself, and only for an id of the minted `<name>-<14 digits>` shape. A phone number in the rest of the run id's name, in the same approval's words or plan title, or the same id typed into `gstack-approvals add`, still refuses.
- Home-directory paths and other low-severity findings stay notes in both `gstack-post` and the pre-merge checks, now pinned by tests, and keys still refuse everywhere, inside /ship's summary block included.
