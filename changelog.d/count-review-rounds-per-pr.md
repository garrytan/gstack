- **`/ship` now counts review rounds per pull request, and the head that merges always gets a full review.** gstack's two-round review cap (R51) was counted inside each `/ship` run, so a PR shipped five times could be reviewed ten times. `/ship` Step 1 now reads the PR body's receipt history (`gstack-ship-receipt history`), prints `PR_REVIEW_HISTORY:` and `PR_REVIEW_ROUTE:`, and passes the earlier rounds to `gstack-review-plan` (`--prior-rounds`, and `--prior-full` for the full rounds the cap counts). A new head whose own lines changed gets a fresh full review, the PR's last before merge; a PR already at two full rounds gets one read-only full review with no fix round, whose blocker goes to the lane's Captain. A scoped re-check of only what changed is now advice only: `carry` prints `RECHECK: advisory` and refuses `--recheck`, because in the replay a diff-only re-check caught none of 8 real faults that full rounds had caught (docs/evals/pr-round-count-results.md). A run that stops before its receipt still counts (`gstack-ship-receipt stub`), and the lane or Captain can buy one more round with `gstack-approvals round-grant --kind extra-round`; gstack cannot grant itself one. See docs/review-policy.md#rounds-per-pull-request.
