- **`/ship` now counts review rounds per pull request, not per run, so a PR pushed many times stops getting a full review at every new head.** gstack's two-round review cap (R51) was counted inside each `/ship` run, so a PR shipped five times could be reviewed ten times. `/ship` Step 1 now reads the PR body's receipt history (`gstack-ship-receipt history`), prints `PR_REVIEW_HISTORY:` and passes the earlier rounds to `gstack-review-plan` (`--prior-rounds`, and `--prior-full` for the full rounds the cap counts). After a full round a new head takes the scoped re-check of what changed since the last reviewed head; a full round comes back when the lane or Captain records a `design-change` grant, when two re-checks found a blocker, or when the PR drifted more than 400 product lines. At the cap the plan stops with `PR_ROUND_CAP` and prints the `gstack-approvals round-grant` command; that call belongs to the lane or Captain, never the owner, and gstack cannot grant itself a round. A run that stops before its receipt still counts (`gstack-ship-receipt stub`), and a re-check reader can now return `"verdict":"blocking"`, which carry records before refusing. See docs/review-policy.md#rounds-per-pull-request.
