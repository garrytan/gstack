- **Syncing a second repo no longer makes the first one ask for /sync-gbrain again.** The GBrain read check looked only at the most recent code sync on the machine, so once you synced another repo, every earlier repo reported itself as unsynced at session start. It now reads the per-repo sync record `/sync-gbrain` already keeps. A repo that never synced still asks, and a record that is missing, malformed, points at another folder, or sits beside a newer failed sync of the same repo never counts as synced. Reported by @SatriaSuriaAriffin (#4499).
