- **Syncing a second repo no longer makes the first one ask for /sync-gbrain again.** The GBrain read check looked only at the most recent code sync on the machine, so once you synced another repo, every earlier repo reported itself as unsynced at session start. It now falls back to the per-repo sync record `/sync-gbrain` already keeps. A repo that never synced still asks, and so does one whose record is missing, malformed or points at another folder, or whose own sync is the most recent on the machine and failed. Reported by @SatriaSuriaAriffin (#4499).
