- **An unattended /ship can now finish a PR that carries an owner-approved gate change, and the lander has to accept each one before it merges.** When the review finds a loosened gate (a test threshold raised, a check skipped), an unattended run logs it as an open gate finding, because nobody is there to answer the gate question, and until now nothing could close it, so the run stopped for good. That blocked founderstar#906, whose gate change Garry had approved. The owner's answer can now be recorded from outside the run with `gstack-approvals gate --finding <fingerprint> --gate-id <gate_id> --head <stop head> --reason '<the gate change>' --words '<the owner's exact words>' --by '<who recorded>'`. It closes only that finding, only on a review whose range holds that head, and the review reader then shows it as kept so the rest of /ship carries on. It is refused while a /ship run is open on that branch in any worktree, without the owner's words, for a literal `undefined` gate id, or when `--by` names gstack. A row that is missing a field the writer writes, or was edited after it was written, is ignored. The lane runs as the same user, so it could still write a row that looks right. That's why the lander decides: `gstack-ship-queue land --pin` works the dispositions out again from the approval store at the pin, prints each one, and merges only with `--accept-gate-disposition <approval id>` for every one. It also refuses when the receipt or the PR body leaves one out or invents one. `gstack-ship-queue verify --pr <n> --pin <sha>` runs the same check without merging, for a lander that merges another way, and `gstack-ship-receipt write` no longer skips the disclosure check when `--body` is left off. Gate findings are logged exactly as before, and a ruling or anything the lane writes on its own review row still closes nothing. A disposition recorded at a commit that a later rewrite removed from the clone just stops applying instead of blocking the branch, and a shallow landing clone is told to deepen itself.
