- **An unattended /ship can now finish a PR that carries an owner-approved gate change.** When the review finds a loosened gate (a test threshold raised, a check skipped), an unattended run logs it as an open gate finding, because nobody is there to answer the gate question, and until now nothing could close it, so the run stopped for good. That blocked founderstar#906, whose gate change Garry had approved. The owner's answer can now be recorded from outside the run with `gstack-approvals gate --finding <fingerprint> --gate-id <gate_id> --head <stop head> --reason '<the gate change>' --words '<the owner's exact words>' --by '<who recorded>'`. It closes only that finding (a further loosening of the same line stays open), only on a review whose range holds that head, and the review reader then shows it as kept so the rest of /ship carries on; and it is refused while the checkout's own /ship run is open, without the owner's words, or when `--by` names gstack. Nothing is hidden: finish prints a `GATE_DISPOSITION:` line for each one, the receipt records it, and the PR body and READY block must carry it word for word. Gate findings are logged exactly as before, and a ruling or anything the lane writes on its own review row still closes nothing.
