- **In Claude Code, a gstack skill's start step now runs when the skill loads, so the model can't skip it.** The start command (`gstack-skill-start`) and the shared preamble file used to be instructions at the top of each skill ("read this file, then run this command"), and models often skipped them: in our test runs, a loaded skill's steps were followed in only 45% to 62% of sessions, and /autoplan's start command never ran in 5 of 10. Now each skill uses Claude Code's `!` command lines, which Claude Code runs while it loads the skill, so the start output and the shared preamble are already in the skill text the model reads. A new helper, `bin/gstack-skill-load`, runs them: it stops the start after 15 seconds (`GSTACK_SKILL_LOAD_TIMEOUT` changes that) and always succeeds, because a failing command would stop Claude Code from loading the skill at all. If something goes wrong, the skill gets one line saying so and the model runs the start command itself, as before. Each skill's `allowed-tools` now names that helper, so it also runs in plan mode. /plan-eng-review and /plan-design-review still run their start command after their scope question, so only their shared preamble loads early.

  **Other hosts:** Codex, Factory, OpenCode, Cursor and every other host keep the old instruction text; only the Claude Code skills changed. If you run Claude Code with `disableSkillShellExecution` on, or read a gstack skill file outside Claude Code, the skill says nothing ran and the model runs the start command itself, as it did before.
