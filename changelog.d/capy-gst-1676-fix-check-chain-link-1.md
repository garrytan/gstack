- **A post-review fix-check chain counts its first link, and the planner plans the next link.** In the post-review flow each granted fix-check's stop head is the commit it reads, so link 1's grant names link 1's own commit, which is also link 2's range_base. finish only accepted an earlier link's grant at a stop head before its commit, so link 1 never counted once link 2 existed and the whole chain routed as behavior (founderstar#634: `FIX_CHECK: not counted (… link 1 of 2)`). A link's grant may now name its own commit; grants are still assigned newest link first, one link per grant, so a lone grant at the boundary covers the newer link only and the older link stays ungranted. `gstack-review-plan --post-review --last fix-check --range-base <last fix-check's commit> --grant <new grant>` now plans the next chained fix-check instead of a stop that asked for the grant it then ignored, and refuses the last link's own grant, so lanes no longer hand-render the dispatch.
