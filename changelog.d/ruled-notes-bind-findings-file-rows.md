- **Owner rulings now close a stopped review whose findings were logged in a findings file.** When /ship's final review was logged with `gstack-review-log --findings <file>`, or the native reader's row listed no findings, `gstack-review-read` had nothing to match the owner's `gstack-approvals rule` rows against, so Step 11.5 stayed unverified even with every blocker ruled (harness-evals#515). It now reads the file's findings onto the row while the file still matches the counts the row recorded, and gives a native row with no findings the same pass's review findings, so the existing rulings bind both rows at the tree they read. A noted CRITICAL still needs its own ruling, an unruled blocker or a pass that didn't complete still refuses, and a row that claims issues but lists no findings now says so in its reason.
