- **The destructive-command check reads commands more carefully, closing gaps found after the last release.** A force-push to `main` is blocked again when written with `git push --repo=origin +main`, after a `cd`, or with `--all` or `--mirror`. A `cd` inside a pipeline no longer makes a later delete look like scratch, and `git reset --hard "$REV"` asks again. It now also asks for quiet `git clean -q`, `--work-tree` and `GIT_DIR` forms, `find -L … -delete`, `rm dir -rf` with flags at the end, `..` paths, a `mktemp` variable pointed somewhere else, a discard after `git stash pop`, and a `terraform destroy` that only had a dry run earlier on the line. It stops blocking `git push -nf` (a dry run) and `wipefs` on image files it names on the command line (any `wipefs -a` fed by `xargs`, or aimed at `/dev`, stays blocked), and stops asking about a grep for SQL text or a folder named `psql`. `GSTACK_SESSION_KIND=interactive` now keeps the ask even when `CI=1` is set. Long commands are checked about three times faster on macOS's bash 3.2.
