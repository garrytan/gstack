- **Pull requests from /ship now open with at most three plain lines, and every merge lands as one commit titled with the PR title.** /ship writes `## ` sections and `gstack-post` folds each into a collapsed section when it posts, so a reader sees what changed, why, and what they have to do, with the rest one click away and the Agent notes section last. `gstack-post fold --body-file F` shows the folded body without posting it. In a repository with `.gstack/plain-titles.json`, `gstack-post` and the Plain title check refuse a body that shows more than three lines (or 600 characters) before its first fold, or uses a listed in-house word above the Agent notes section (`PLAIN_BODY_REFUSED`); gstack now ships a default word list (outside voice, pregate, receipt, carry, stamp, train, lane, soak and more), which a policy extends or replaces with `replace_default_terms`, and `body_since` keeps PRs opened before that date to warnings. Every `gstack-ship-queue land` form now passes the subject `<title> (#n)` and a body of the PR's opening lines plus the branch's `Co-authored-by:` and other trailers, so GitHub no longer writes its commit list; `--dry-run` prints it and `--body-file` replaces the opening. Release PRs list one plain line per change with its PR. Two new policy settings: `history: no-rewrite` (squash landings, never a rebased or force-pushed branch) and `land.merge_commit_paths` (keep a merge commit for PRs that change those paths, such as eval results). See docs/writing-prs.md.
