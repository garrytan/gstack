**The second-model review now keeps the reviewer's own result, and reports a used-up budget as a budget stop.** Two fixes to the Codex review that /autoplan, /review, /ship and the other skills run:

- When the reviewer wrote its review to the result file it was asked for, Codex then replaced that file with its short closing message ("Done, I wrote the review"), so the review was thrown away and reported as missing its markers. Codex's closing message now goes to a separate `.last-message` file, and gstack keeps whichever of the two carries the review.
- When the provider refuses the call with HTTP 402 Payment Required (usually a metering proxy that hit its allowance, or an account out of credits or quota), gstack used to record only "exit 1". It now reads the cause from Codex's JSON error events and reports "the provider refused the review with HTTP 402 (payment required)", and says to check the proxy's allowance, or the account's quota and credits. It has its own reason code, `budget_exhausted`, in the run record and in docs/troubleshooting.md, and the skills' "authentication failed, run `codex login`" rule no longer fires on it. A 401 or 403 is still a login problem, and its record now keeps Codex's status line instead of "exit 1".
