- **/ship's documentation audit no longer halts when the audit child writes prose after its result.** Step 14.5 read only the child's last nonempty line, so a child that ended with its JSON result and then restated the documentation section in prose (founderstar #837 and harness-evals #393, both "docs current, no edits") had its result rejected as `DOCS_RESULT_INVALID` with no format repair. Each rejection spent one of the two audit attempts, and after both /ship stopped for an owner risk grant. `gstack-docs-candidate result` now reads the last line that opens a JSON object and ignores prose after it, printing `TRAILING_PROSE: ignored <n> lines after the result object`. A result that is only missing `documentation_section` gets the existing free re-ask, which now tells the child to put the section inside the JSON as a string and write nothing after the line; the re-audit's retry note says the same. Results with a missing audit id or status, or a status that contradicts the file lists, still count as an attempt, and nothing is ever filled in for the child (GST-2349).
