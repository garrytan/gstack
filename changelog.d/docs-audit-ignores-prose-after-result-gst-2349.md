- **/ship's documentation audit no longer spends an attempt when the audit child writes text after its result.** Step 14.5 reads the child's last nonempty line. A child that ended with its JSON result and then restated the section in prose (founderstar #837 and harness-evals #393, both "docs current, no edits") had its result treated as unreadable content, which skipped the free format re-ask. Text after a JSON line that carries the audit id is now a format slip: `FORMAT_REPAIR:` re-asks once for the whole result line without spending an attempt, and the reply is judged on its own. Nothing is ever taken from the earlier line or from the trailing text, so a later correction or a fenced example can't change the verdict. The re-ask and the retry note now tell the child to put the section inside the JSON as a string and write nothing after the line (GST-2349).
