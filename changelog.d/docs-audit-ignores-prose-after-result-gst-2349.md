- **/ship's documentation audit no longer spends an attempt when the audit child writes text after its result.** Step 14.5 reads the child's last nonempty line. A child that ended with its JSON result and then restated the section in prose (founderstar #837 and harness-evals #393, both "docs current, no edits") had its result treated as unreadable content, which skipped the free format re-ask. Each rejection spent one of the two attempts, and after both, /ship stopped for an owner risk grant. Text after a JSON line that carries the audit id is now a format slip, provided every such line is free of content problems: `FORMAT_REPAIR:` re-asks once for the whole result line without spending an attempt. The re-ask only works one way. If any JSON line for the audit said blocked or listed a blocker, no later JSON line, fenced or not, and no re-ask reply can turn it into a passing result: the result must stay blocked and keep those blockers. A blocker written only in prose after a passing line goes to the re-ask, which is told to count it, but the parser cannot check that it did. A content problem on such a line (a missing status, "current" with edits) still spends an attempt. The re-ask and the retry note now tell the child to put the section inside the JSON as a string and write nothing after the line (GST-2349).
