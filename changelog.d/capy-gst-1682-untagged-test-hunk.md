- **An owner's review-loop exception can route a type-only test edit it names.** After round 2, a one-line test edit that only widened a TypeScript cast (`as unknown as { attest?: … }` gaining `sources: string[] | null`) was forced as changed since review, because any test hunk that removes a line counted as a possible gate edit unless it was literal-only, so `--review-loop-exception` could not route it and the lane needed another grant and fix-check for a cast (GBRA-336). A `.ts`, `.mts` or `.cts` test path the exception's `fix_check.files` names now routes as accepted when gate-diff leaves it untagged, it imports something (so Bun runs it as an ES module), and the whole file before and after transpiles to byte-identical JavaScript under `Bun.Transpiler` with pinned options, which means only types or comments changed, and its leading comments (everything above the first line of code, `#!` included) are byte-identical, because Bun, Jest and Vitest read pragmas such as `// @bun` or `@jest-environment` there. The pins stop transpiler defaults from hiding an edit (`NODE_ENV` inlined from the running process, a declared `__dirname`, a decorated member's type). A parse error, a non-TS or CommonJS file, a pragma added at the top and any other difference stay forced, and an unnamed path never routes this way. (GST-1682)
