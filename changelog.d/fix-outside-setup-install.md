- **TypeScript hooks start on Windows when Git Bash leaves a path unconverted.** Under a home folder holding an apostrophe (such as `C:\Users\O'Brien`), or with `MSYS_NO_PATHCONV=1` or `MSYS2_ARG_CONV_EXCL=*` set, every TypeScript hook died with "Module not found" and `gstack-hook-check` reported all of them broken. Each hook now hands Bun its own folder in `C:/…` form, the checker does the same, and `./setup` turns Git Bash's path conversion back on for the programs it starts. (#4386)
- **`./setup --status` passes on a `--prefix` install.** It no longer reports `gstack-review/SKILL.md names ../qa/sections/exploratory.md` as broken when the prefixed `../gstack-qa/…` path the same file names exists. (#4164)
- **`./setup --status` names commands that clear what it reports.** A row whose install root is gone now says `./setup --refresh-registered` drops it, and the gstack checkout's own Codex render is no longer listed as an unregistered project install. (#4420)
- **`./setup` no longer leaves owner-only files in Bun's shared package cache.** Its `bun install` and Playwright install run under umask 022, so another project that later reuses the same cached packages can be read by other users; gstack's own state and logs stay owner-only. (#4288)
- **Disabling `/open-gstack-browser` also removes its `/connect-chrome` alias.** (#4308)
- **`gstack-doctor` no longer flags gstack's own CLAUDE.md as a pasted skill list** when run inside a gstack checkout. (#4324)
- **OpenClaw, Hermes and Dots registrations leave out skills turned off with `disabled_skills`.** (#4548)
