**/cso reports every security finding the code supports instead of dropping most of them.** On 52 real GitHub security advisories, /cso named the published flaw in 3 of 51 audits where a plain audit request named 12. It ran out of its 10-minute budget reading one file per helper call, it was told to keep only findings proven inside the repository (which drops most library bugs), and the helper refused anything less in a daily run. Now `gstack-cso search <run> <regex>` searches every file in the snapshot in one call and names any file it could not search, a library's public API counts as an attacker entry point, and a finding with one open question is kept at low confidence under "Hypotheses (unconfirmed)" in the saved report instead of disappearing. A refused start is now retried with the correction it names.
