- **/ship no longer kills a working test run as stalled when the test command starts its workers in their own session.** The stall check read CPU time from the test command's process group only, so a quiet suite run through a launcher that starts its workers in a new session (pnpm 11's `pnpm exec` running Vitest) looked idle and was killed as `PREGATE_STALLED`. It now counts every process descended from the command, and a stall or timeout kill reaches those workers too. A truly hung run is still killed at the same stall timeout. Reported by @dtoelke in #4477.
