**`/gstack-ship` no longer forces a whole new full review after the Captain rules in a small edit made after the final review.** The planner stopped because the release stamps written after review (VERSION, CHANGELOG) were never ruled, and the receipt refused the targeted reader's record from before the edit. Now stamps need no ruling, a ruled edit that touches no money, gate, auth or secret code keeps that record (the receipt lists the rulings), and a ruled edit that does touch such code gets one targeted reader instead of a full review. A ruled edit to a doc the docs audit checked no longer reports the docs as stale, and the targeted reader's own pass no longer shows as unbound. Inside a git worktree, gstack no longer crashes with ENOTDIR when git can't name its directory; it reports the git failure. Carrying a ship receipt across a merge of main also works when main made one of the PR's exact changes itself, such as deleting the same entry; a merge that drops or edits any other change still needs a new review.
