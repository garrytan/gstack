### Fixed

- **`gstack-pr-wait` no longer blocks on a cancelled check that a newer passing run of the same check replaced.** In a repository whose workflows use `concurrency: cancel-in-progress`, the older run is cancelled when the next one starts; `gstack-ship-queue ready` already judged the check by the newer pass, but `gstack-pr-wait --until green` stopped with `PR_WAIT_BLOCKED`. It now waits while the newer run is going and goes green when it passes. A failed run beside a newer pass still blocks, and so does a cancel that is the newest run (#4807, reported by exGeni).
- **The `DEPS_MISSING` stop names npm's `allow-git` setting when the lockfile installs a package from git.** npm 12 refuses git packages by default, so the plain `npm ci` the stop suggested failed with `EALLOWGIT`. The hint still suggests `npm ci` and says to add `--allow-git=all` if you trust that source; gstack does not turn it on for you (#4815, reported by exGeni).
- **The docs audit /gstack-ship launches starts after a reviewer's install replaced the shared install verdict.** A `--for review-voice` install rewrote the shared verdict, so the `document-release` child was refused at start even though /gstack-ship's own install had certified the same checkout and HEAD. When a reviewer's install wrote the shared verdict, admission now also tries /gstack-ship's own record, with the same checks. A launch refused this way and reported as an empty blocked result no longer uses up the PR's one re-audit.
- **`gstack-ship-receipt write` leaves a retired `scoped-fix-check` row out of `--no-stop`,** as `gstack-no-stop` already refuses one.
