- **A data file with a config-style name, such as a results `manifest.json`, now leaves /ship's review diff when the base branch's `review_exclude_paths` names it by file name.** Files named like tool config (`manifest.json`, `package.json`, `tsconfig*.json`, files under `config/`, dotfiles) were always kept in review as config, even under a pattern written for them, so a large eval results PR whose base policy listed `docs/benchmarks/*/results*/**/manifest.json` still handed every reader its 1.42 MB manifest and stopped at `REVIEW_DIFF_TOO_LARGE`. The kept manifest also counted as code that names files, so every receipt it listed by full path stayed in review as `named-by-code`. Now a matched JSON, CSV, TSV or image file is treated as data when the pattern that matches it ends in its exact file name with no glob character. Such a file is excluded, and its list no longer keeps other files. A config file under a broader pattern (`data/**`, `**/*.json`) is still kept as `config`, config files no pattern matches are unchanged, and every other keep rule (gate paths, executables, secret lines, gate tags, `.gstack/` and `.github/`) still applies first. The policy is still read only from the base branch.
