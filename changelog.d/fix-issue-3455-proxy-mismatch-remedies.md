**When `browse` refuses a running daemon because its proxy settings differ, every fix it suggests can now be followed.** A session started with `--proxy` against a daemon that was opted out of the system proxy gets the plain `--proxy` refusal instead of advice that `--proxy` overrides. The advice to unset a variable names every proxy variable still set in the shell, so the next run is not refused for the one left behind. A session with `BROWSE_PROXY_URL=direct` meeting a daemon that uses `HTTPS_PROXY` or another standard variable is told to unset `BROWSE_PROXY_URL` first. A `connect` daemon whose proxy differs as well as its headed mode now adds a line naming the variable, since passing the same flags alone would not reuse it. Contributed by @Barack-zero-to-one
