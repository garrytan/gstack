- **/ship's reviewers now state how many findings block in one machine-readable line, and gstack checks that count instead of guessing from their prose.** Every blocking reader's brief asks for `REVIEW_VERDICT: blocking=<n>` (with optional `at=<path>:<line>` locations). When the count is higher than the findings gstack parsed, collect adds a CRITICAL row for each missing blocker, so a blocker written in a form the parser misses can no longer vanish. When it is lower, nothing is lowered automatically: rows that block only because a sentence used the word CRITICAL or P0 become summary candidates the lead may lower with a written reason, and the native adversarial voice's 'all FIXABLE, nothing blocks' sentence keeps its own label. A missing or malformed line changes nothing. Ledgers written before this change replay exactly as before. See docs/review-policy.md#verdict-line.
