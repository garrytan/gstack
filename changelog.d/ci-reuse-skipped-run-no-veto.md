**A skipped CI run no longer blocks reuse of a passing run on the same commit.** When a workflow fired twice for one commit, say a manual dispatch plus a pull request run whose jobs all skipped, the skipped run was treated as a newer failure: `gstack-pregate` refused the passing run with `newer_run_vetoes`, and `gstack-ci-carry wait` reported the commit red. Both now pass over the skipped run. A newer failed, cancelled or still-running run still blocks reuse.
