**`gstack-harness register` now writes frontmatter a strict YAML loader accepts, so Pi (and any other harness that parses frontmatter with YAML) actually gets the gstack skill (#4163).** The router description ends `... Load first for any coding task: lists every gstack skill ...`, and both frontmatter writers in `lib/harness-register.ts` emitted it as a plain scalar; an interior `": "` is a nested mapping to a YAML loader, so Pi rejected the file and dropped the whole skill as malformed while `register` still reported "1 files written". #1778 fixed exactly this in the doc generator, with a helper local to `scripts/gen-skill-docs.ts`; it now lives in `lib/yaml-scalar.ts` and `routerSkill()` (router mode, the failing path) and `flatFrontmatter()` (`--skills all`, where any skill description containing a colon broke the same way) both use it. A value that is already a valid plain scalar passes through unchanged, so no other host's render and no committed `SKILL.md` changes bytes — the generator's output is byte-identical (`gen-skill-docs --dry-run` exits 0). Tests cover the registered router frontmatter reading back through `JSON.parse` and a colon-free description staying unquoted.
