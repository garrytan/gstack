**`/gstack-ship` closes five gaps in how it records reviews, and `--for gstack-ship` now installs the ship skill on Capy.** A ruled docs edit that adds a money, security or numeric claim now needs a fresh targeted read in both the review plan and the receipt; before, the receipt accepted the old read while the plan asked for a new one. A targeted-only read after the loop no longer hides an earlier full pass that stopped before its findings were logged. When a review is split into slices, a targeted record is no longer marked done if the slices don't cover the diff exactly, and a retry after an outside reviewer's cyber-policy refusal now skips the native reviewer's model family even when the native reviewer was sliced. `gstack-ship-budget check --next dispatch:<role>*<k>` reserves one reader per slice, so a sliced review is priced before it runs. The Capy skill now says `/gstack-ship` throughout, and the troubleshooting entry for `RECEIPT_CARRY_PRODUCT_CHANGED` lists the base-merge case that `docs/ship-policy.md` already allows.
