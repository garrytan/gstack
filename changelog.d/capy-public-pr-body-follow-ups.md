**`/gstack-ship` stops mistaking ordinary text for Capy ids, and checks every part of a public PR body it posts.** Text such as `SHA-256:abc`, `UTF-8:x`, `PR-12:fix` or a file named `test/jam_fix.ts` was refused or replaced by "a private message" on public repositories; now only real Capy ids (`jam_`, `icm_`, `iev_`) and relay refs whose message part is a Capy id or a timestamp count, and a relayed ruling still reads "relayed from a private message" whatever its ref looks like. On a public repository, `gstack-ship-receipt` write, carry and abandoned now also refuse a home folder path or Capy id in the earlier-runs block and abandon reasons, not only in the receipt. `gstack-ship-receipt abandoned --pr` marks only an open PR that records the run, and reads the repository the branch pushes to (its `pushRemote` or `remote.pushDefault`, else `origin`, at that remote's push URL), so contributors whose `origin` is upstream can use it once one of those names their fork. On private repositories, the merge check again accepts a `Gate disposition:` line written before ids were redacted, and a hand-edited earlier-runs entry with a non-text run no longer crashes the round count.
