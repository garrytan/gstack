- **An outside review now counts as clean only when the reviewer's last line is exactly `VERDICT: CLEAN` or `VERDICT: FINDINGS`.** Every outside-review prompt (in /ship, /review, /codex, /claude-code, /autoplan, the plan reviews, /office-hours, /design-review and /document-release) now asks for that line, and gstack no longer reads prose such as "No issues found in the diff." as a pass. Every earlier rule for reading a no-findings sentence let some reply that named a problem pass the merge check, for example "The fallback swallows ENOENT; no issues in the diff.", a clean Recommendation followed by a listed problem, "No issues found in the latest commit." on a whole-branch review, and "Recommendation: fix the auth bypass because no issues in the diff." A reply without the line now reads `VERDICT: unverified` / `REASON: missing_verdict`: missing coverage, never a pass. A P0 or P1 finding (or a Critical or High label) and a last `Verdict: not ready` still block whatever the line says, and advisory P2 or P3 findings still pass. Codex's structured outside review in /ship and /review, and the default `/codex review`, now run through `codex exec` with gstack's prompt instead of `codex review --base`, which takes no prompt and so could never give the line. The diff they review is the same (`git diff $(git merge-base <base> HEAD)`: the branch commits plus uncommitted tracked edits). Skills rendered before this change still read unverified until `./setup` re-renders them. A reply that ends with `VERDICT: CLEAN` but lists numbered items with no severity tag now reads `VERDICT: unverified` / `REASON: untagged_review` in /ship and /review, and a `/codex` consult or challenge answer with numbered items and either a `Verdict:` line or a last `VERDICT: CLEAN` now prints `FINDINGS: unspecified`. `/codex review` now stops before calling Codex when it cannot write the diff into the prompt. See docs/troubleshooting.md#outside-review-missing-verdict.
