- **The CI carry now accepts a run where only an unrelated job was rerun.** Rerunning one job of a green run (a flaky `public-export`, say) made GitHub number the run's newest attempt 2 while the checks job, which wasn't rerun, still carried its attempt-1 `tree.json`, so `accept` refused with `artifact_mismatch`; rerunning the checks job too left two same-named artifacts and refused with `artifact_missing`. Run verification now works out which attempt each profile job actually ran in (GitHub relists a job it didn't rerun with its old start and finish times) and checks `tree.json` against that attempt, and with one artifact per attempt it reads the one from the uploading job's newest attempt. Every other field (head, merge commit, tree, event, job conclusion) is still compared exactly, and an older attempt's artifact is never read in place of the newest. The 24-hour freshness check now dates a run by its own test jobs, so rerunning an unrelated job never makes days-old results look fresh. When the pregate's skipped-tests command fails because the checkout has no installed dependencies, the refusal now says so (GST-2284, harness-evals HARN-56).
