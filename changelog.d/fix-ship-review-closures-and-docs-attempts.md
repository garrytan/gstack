**`/gstack-ship` stops reopening findings that were already settled, and a missing run folder no longer costs a docs-audit attempt.** A finding the owner ruled as a note stays ruled when edits above it move its line (the ruled line itself unchanged); a different finding in the same file, or the same line after its text changed, still needs its own ruling. A blocker fixed in a commit with no `Review-Finding` trailer now closes when that commit changed the finding's own line after it was raised and a later full review, the read-only final review included, read the whole branch clean. Lines under a reviewer's "What I checked and found sound" list no longer count as blocking findings unless written as one, such as a line tagged "(Critical)"; a heading that only mentions a sound phrase still counts every finding under it. The docs audit's snapshot refuses up front with `DOCS_RUN_FOLDER_MISSING` when its run folder does not exist yet, so that setup mistake spends neither of the step's two attempts.
