Review now keeps a file in view when a branch replaces your own code, or drops a local patch, so the file matches an upstream copy byte for byte. A changed file counts as vendored only if it was already vendored and verified at the merge base, or is new on the branch. `gstack-vendored-verify` also caches the merge base's pins for the files a branch changes or deletes, so later offline steps can answer, and a failed fetch no longer wipes earlier good answers from the cache (docs/vendored-code.md).
