- **/ship's token cap counts /ship, not the whole thread tree.** A /ship subagent can read only the root thread, whose counter also holds the lane's own fix work, background suites and trail reads, so lanes kept hitting /ship's cap for spend that was not /ship's (about eight cap-raise round trips on #4096-#4101). `ship/DRIVER.md` now writes each program's `tools.thread.get` result to a file and passes `gstack-ship-budget … --thread <file>`: the helper finds /ship's own task row (the brief's `GSTACK_SHIP_TASK_TITLE` row, or the parent of a reader the run dispatched), caps that row with its readers, and prints both numbers, `used=<ship> tree=<thread>`. Where /ship's share can't be separated (before its first reader with no task title, or /ship running on the root thread), the run meters the tree and says why on a `METER_FALLBACK:` line. A `--thread` run that names no cap keeps the 100M default cap whatever it meters, its own row or the tree, and if /ship's row drops out of a truncated task list, `used=` grows with the tree (an upper bound) instead of standing still. A pass's `readers_tokens` now comes from its readers' own rows. (GST-1699)
