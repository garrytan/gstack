- **A policy edit that changes nothing about a PR's files no longer forces another review.** After main's `review_exclude_paths` gained patterns that match none of a PR's files, `gstack-ship-receipt write` refused the digest the reviewers read, and ready, carry, train build and land bound it only when both selections were empty (harness-evals #222: its reviewers read 7cf39a7e1150, which excludes 1,260 of its files, and write refused after #278 added six globs that match none of them). The shared check now binds when the recorded selection and HEAD's give the PR's files the same applied patterns, excluded files and kept files. Write gets only the digest, so it rebuilds the recorded selection from the policies the base held and prints `REVIEW_EXCLUDE_POLICY_MOVED:`. A selection that differs, a digest no base policy gives, an omitted `--review-exclude` and an unreadable base policy still refuse. (GST-1446)
