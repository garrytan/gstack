### Fixed

- **Results PRs that capture model requests no longer stop at the review ceiling just because their captured prompts mention credentials.** A file under `review_exclude_paths` stays in review when a changed line reads a credential, and until now every such file went to each reader whole. On harness-evals #269, 75 captured requests whose system prompts name `${…_API_KEY}` variables and keychain commands added 12.9 MB, and `/ship` refused with `REVIEW_DIFF_TOO_LARGE` against the 2 MB limit. When the secret line is the only reason a file is kept, `gstack-review-dispatch pass` now gives readers an excerpt instead. The excerpt holds every changed line the secret-line rule matches or the credential scanner finds a secret-shaped value on, with up to 3 lines of context, the path and the match counts. Only the excerpt counts toward the limit. A file kept for any other reason (a program names it, it is outside the applied patterns, the gate or name scan could not run) is still shown whole, and so is any file whose excerpt cannot be built. See [secret-line excerpts](docs/ship-policy.md#secret-line-excerpts).
