**The secrets check catches more Google API keys in encoded text, reads each JavaScript and TypeScript declaration under its own name, reports a provider key once, and stops matching look-alike values against your environment's secrets.** A Google API key inside a long block of base64 text is now reported when its characters show it can't be part of that block. In a line that declares several names, a key is checked under the name it is assigned to, so a hash after a secret-named variable no longer reads as that secret, and a key assigned to a secret-named variable that follows names declared without a value is now caught. A provider key in a `const` (such as a public Firebase key) now reports only under its provider's rule, so allowlisting that rule clears it. A value that differs from one of your environment's secrets by one character no longer matches that secret's base64 form, while the secret's own base64 form still reports. (GST-4104)
