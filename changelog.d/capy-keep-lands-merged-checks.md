- **`gstack-ship-queue land` runs `land.merged_checks` in a fresh clone and stops when a check touches anything land's later git or gh calls read.** The merged-tree checks now run in a clone outside the checkout, with its own `.git` and a copy of `node_modules`, so what a check writes to its hooks, config or modules is thrown away with the clone. Before the checks, land pins the absolute `git` and `gh` it runs and puts their directories first on its own `PATH`, and it records the checkout's git config, hooks, `commondir` and `gitdir` files and `.git`, every config file git loads there (includes and the global file among them), gh's config and hosts files, the pinned binaries, and every symlink hop among them. When a check changed any of them, land refuses with `QUEUE_LAND_MERGED_CHECKS` naming each path and a hold-and-inspect fix, makes no further git or gh call and leaves the land lock held; after restoring the named paths, `gstack-ship-queue land --pr <n> --pin <sha>` without `--allow-repo-commands` releases the lock without running the checks. Every git call `gstack-ship-queue land` makes runs with `core.hooksPath=/dev/null` and `core.fsmonitor=false`; other queue commands keep the checkout's hooks. (GST-1747, GST-1766)
- **`gstack-ship-queue land` can run full CI on the merged tree before it lands a PR whose base moved.** A new `land.merged_ci` key (`{ workflow, profile }`) makes land push the PR merged onto main's tip to a scratch branch, dispatch that workflow there, wait, and land only when the run passes the named run profile with the merged tree as its tested tree; a red run refuses with `QUEUE_LAND_MERGED_CHECKS`. gstack's own policy now runs the whole free suite this way, so no PR reaches main on a base its tests never saw. (GST-3303)
