**Landing a PR no longer starts a new CI run when one for the same merged code is already running or has passed.** When main had moved, each `gstack-ship-queue land --pin` dispatched a fresh Free Tests run on the merged tree and gave up after 45 minutes, so a slow macOS runner queue refused the land, and the next try queued yet another run while the first one finished green unused. Land now reuses the newest earlier run on the same merged tree. It lands at once on a green run, waits on one still queued and refuses on a red one, and a timeout names the run the next try will wait on.
