**/ship no longer asks for a fresh review because of a stacked parent that main already had.** When a PR was reviewed after its parent had squash-merged into main, and then merged main again, /ship measured from the parent's old commits and refused over the parent's files. It now measures from the merge base, so an unchanged PR keeps its review, and context that main moved next to the PR's own lines gets one scoped review of just that file (yc-software/qm#3457). The patch comparison also always uses three lines of context, so a `diff.context` setting in your git config can't hide moved lines.
