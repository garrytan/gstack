- **Ubicloud fan-outs can no longer overshoot the vCPU limit, and owners no longer delete each other's VMs.** `ubi-runner.sh up` now reads the project's vCPU usage and books its new VM under one lock per machine, so shards started together see each other's bookings instead of all passing on the same reading. A new `ubi-runner.sh room [-s SIZE]` command prints how many more VMs fit now, so a fan-out can size each batch to the room left. When usage can't be read and `UBI_QUOTA_VCPUS` is set, the create is refused (`UBI_QUOTA_UNREADABLE`) instead of going ahead. VM names now carry the whole owner id (up to 31 characters; longer is refused with `UBI_OWNER_TOO_LONG`) instead of its first 12, so two owners sharing a prefix no longer reap each other's expired VMs (#3748); a VM an older runner copy named under the old cut form is still reaped by the long owner on the machine whose VM record lists it, and `recover` accepts the longer owner ids. Merge checks and canaries set no `UBI_QUOTA_VCPUS` and behave as before.
