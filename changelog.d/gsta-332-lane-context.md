### Changed

- **Crew lanes keep their context cheap, and docs/captain.md says how.** A new "Lane context" section covers four habits. A lane that expects a wait under about 30 minutes checks in every 240 seconds, so its prompt cache stays warm; a cold restart after five idle minutes costs about eight times as much as a warm step. Longer waits still sleep, the controller never warm-waits, and a lane still sleeps while /ship runs. Independent reads go in one parallel program, each call returns 4k characters or less, and long output goes to files. A lane past twice the crew's median lane spend writes `handoffs/<code>/next.md`, and the controller decides whether it continues, rotates or parks, below the existing stop at three times the median. The brief template gains a `Read:` line and a `Context:` line that say the same, and docs/unattended.md notes the warm-wait exception.
- **The gstack Capy skill has a lane start card.** `capy/skill/gstack/lane-card.md` (about 1,100 tokens) is what a crew lane reads once its install check passes, instead of the rest of the skill's SKILL.md. It points to the SKILL.md /ship sections, which lanes still read before shipping. SKILL.md stays inside its 5,315-token context budget. Owners copy the skill folder as usual to pick it up.
- **AGENTS.md lists skills by name only.** The catalog tables, about 9.8 KB that every agent reading AGENTS.md loaded each session, are now a names-only index of about 2.7 KB that points to docs/skills.md for what each skill does. Validation discipline, build commands, platform support and key conventions are unchanged. The /cso runtime and scanner catalog details that lived only in AGENTS.md moved to docs/skills.md.
