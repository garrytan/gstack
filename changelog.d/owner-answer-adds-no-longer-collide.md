- **Two `gstack-owner-answers add` runs for the same answer no longer collide.** When two processes recorded the same owner answer at once, about one pair in ten failed: one could read the other's row while it was still empty and report a conflict, or see the record's folder appear between two checks and refuse it as "a link that cannot be resolved". The second add now waits up to 2 seconds for the first to finish writing, and the folder check looks for the folder before resolving it. Three tests that failed intermittently under load also got fixes. The sealed-guard streaming test now treats Bun's buffer-overflow error as a failure even when git exits 0, and the two `gstack-ship-receipt` test files use the same 30-second limit as CI.
