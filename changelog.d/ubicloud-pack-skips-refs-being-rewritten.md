- **Packing a checkout for a Ubicloud run no longer fails when git beside it is rewriting a ref.** `ubi-runner.sh pack` asked git's upload-pack for every ref, and upload-pack advertises a ref it cannot read (a loose ref file caught mid-write or mid-delete) with a null id, so the snapshot failed with "not our ref 0000…". Pack now reads the refs once with `git for-each-ref`, which skips an unreadable ref, and fetches those exact objects. Seen twice in Free Tests on 2026-11-17 (runs 44063454800 and 44050883970); an empty loose ref file reproduces it every time.
- **The /plan-ceo-review HOLD SCOPE eval no longer fails a review because its follow-up question didn't repeat the mode name.** The check required the decision's "Project/branch/task" line to say "HOLD SCOPE", which the skill never asks for; the decision is already tied to the HOLD answer by session and order. A line naming another mode, or past or hypothetical work, still fails.
