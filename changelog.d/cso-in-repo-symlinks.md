- **`/cso` now audits a repository that tracks symlinks.** A single symlink anywhere in the checkout used to stop `gstack-cso start` with `UNSAFE_PATH`, even a relative link such as `CLAUDE.md -> AGENTS.md`. A link whose target resolves to a file or directory inside the repository is now recorded as an exclusion in the report's snapshot-inputs coverage and never followed; its target is handled under its own path. A link whose target is not audited, because it is ignored, is Git metadata or lies outside `--paths`, counts as a coverage gap. Links that are absolute, escape the repository, are broken or loop, or point at a FIFO or device are still refused. A link inside a host dependency tree such as `node_modules` is excluded with the rest of that tree, and one outside `--paths` is listed as out of scope; neither is resolved. A `--paths` entry that is itself a symlink is refused with the path it points to, and an untracked FIFO or a symlink outside `--paths` no longer blocks the run.
