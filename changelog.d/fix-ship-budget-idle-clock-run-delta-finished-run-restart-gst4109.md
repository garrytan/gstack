**`/gstack-ship` no longer stops or blocks because of time and tokens that belong to something else.** The 100-minute stop now counts active minutes: a stretch of more than 5 minutes with no gstack call (waiting on CI, a reviewer or a Captain's ruling) counts only its first 5 minutes, and only calls in the run's own checkout count, while a run that keeps calling gstack still stops at 100. A new `/gstack-ship` that reuses an earlier run's record now starts its own run instead of joining the earlier one, so the token cap and the clock count only this run's own use; `resume` still continues an earlier run and is still the only way past a budget stop, and `resume --meter capy` now needs `--reading` instead of counting the thread's whole counter. A run whose budget closed at its last step now marks its run record finished, and the next preflight ends one an older gstack left open, so a finished run no longer blocks the next `/gstack-ship` on the same checkout while a run still in progress keeps blocking. `gstack-ship-run abandon --run unknown` with an open PR no longer suggests a PR-body command that refuses the same way, and a PR-body mark that the PR refuses prints why without a rerun hint.
