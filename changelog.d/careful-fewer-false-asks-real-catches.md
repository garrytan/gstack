- **The destructive-command check stops asking about scratch deletes and catches the real damage it used to miss.** Deleting anything under `/tmp`, a `mktemp` folder, a cache or build output no longer asks; in a replay of 254,322 agent commands those were 95% of its false asks. It now also asks before deletes outside the session's folder (including `rsync --delete` and `find -delete`), git commands that would throw away uncommitted work (only when the tree really has some), history rewrites, remote branch deletes, database resets and cloud deletes, and it reads every command in a chain on its own. A recursive delete of `/`, your home folder or a system folder, a force-push to `main` or the default branch, and wiping a whole disk are now blocked however the command is written. `DROP TABLE` and `TRUNCATE` ask only when a database client runs them, so the words in a grep or a test file no longer do. Harnesses that run Claude Code with nobody watching can set `GSTACK_SESSION_KIND=unattended` so asks become warnings.
