**`/gstack-ship` no longer puts home folder paths or Capy thread and message ids into PR bodies on public repositories.** The ship receipt stored `--run` as given, so runs that passed their run folder's path published `/home/<user>/...`. It now keeps only the folder's name, both when writing and when carrying a receipt to a new head, and older receipts that still hold the full path keep matching their run. On a repository GitHub doesn't report as private (checking the `--repo` a command publishes to as well as the checkout's own), a receipt that would still hold a home path or a Capy id (`jam_`, `icm_`, `iev_` or `<thread>:<message>`) in any value or key is refused before anything is written or carried. A ruling relayed from a Capy message reads "relayed from a private message" in `gstack-approvals rulings`, in finish's output and in the receipt, and a Capy id in a ruling's ruler or reason, or in a gate disposition's recorder, reason or words, reads the same way, so a PR carrying a Captain's ruling still gets a clean receipt. The approval record keeps the real references. `gstack-ship-receipt abandoned` refuses a PR whose head isn't this checkout's branch on its origin repository, instead of marking someone else's or a fork's PR, and leaves Capy ids out of the entry it writes on a public repository.
