**`/gstack-ship` no longer puts home folder paths or Capy thread and message ids into PR bodies on public repositories.** The ship receipt stored `--run` as given, so runs that passed their run folder's path published `/home/<user>/...`; it now keeps only the folder's name, and matching against older receipts that still hold the full path keeps working. On a repository GitHub doesn't report as private, a newly written receipt that would still hold a home path or a Capy id is refused before anything is written. A ruling relayed from a Capy message now reads "relayed from a private message" (and a Capy id in its ruler or reason reads the same way) in `gstack-approvals rulings`, in finish's output and in the receipt, all the same way, while the approval record keeps the real reference. `gstack-ship-receipt abandoned` refuses a PR whose head branch isn't the checkout's branch, instead of marking someone else's PR, and leaves Capy ids out of the entry it writes on a public repository.
