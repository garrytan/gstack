- **The update-channel tests can no longer write your real gstack config.** `test/update-channel.test.ts`'s `gstack-config` case wrote `update_channel` into whatever `GSTACK_STATE_ROOT` the shell exported whenever the run skipped this repository's `bunfig.toml` preload (a run from another directory, or `bun --config=/dev/null test`), which could flip a developer's or crew machine's update channel. The `runBin` helper's `gstackHome` option now points all three state-root variables at the test's directory, every spawn in that file starts from an environment with the state-root chain removed and HOME in a temp dir, and a new guard (`test/state-root-isolation.test.ts`) runs both update-channel test files with `GSTACK_STATE_ROOT`, `GSTACK_HOME`, `GSTACK_STATE_DIR`, a live `CLAUDE_PLUGIN_DATA` and HOME exported to sentinel directories and fails if any of them changes. The install fixture also stops treating a worktree's `node_modules` symlink as source, so `update-channel-setup.test.ts` and the other real-setup tests run from a worktree that shares its main checkout's dependencies.
