**Crew PRs now show whether they had their plan step, and a repo can require it (GST-1751).** In qm, a Captain's brief replaced /autoplan with "light plan … no gate to Garry" for a new UI feature (qm#3186), and nothing noticed. A PR now carries its brief's `Plan:` line under `## Approvals` (`gstack-approvals render --plan "<line>"`): `approved: <autoplan run id or approval row id>`, `exempt: <reason>` from docs/captain.md's list, or `required`. `gstack-ship-queue ready` resolves it against every branch's approval rows, prints `PLAN:` and writes the result into the READY note, and `land` checks the note still matches the PR body. A gate the lane answered in its own words, a newer gate revision that isn't approved, and a ruling or grant row never count as the owner's plan approval; imports now record `words_by` for that. gstack never guesses from the diff or the title whether a change is a feature: no line reads as `required`, and a diff of changelog fragments only needs none. The new `plan_record` ship-policy key is `off` by default; Capy crew sessions warn, and `require` (policy or `GSTACK_PLAN_RECORD=require`) refuses with one of six codes, each with a fix. `gstack-approvals plan-check --plan "<line>"` checks a line by hand. Replayed on the last 60 merged gstack PRs with each PR's brief line, 57 pass and 3 would be refused: two features Garry approved where no approval row was ever written (#4100, #4055), and one whose gate the lane answered in its own words (#4049).
