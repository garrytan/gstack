**A neutral CI run no longer blocks reuse of a passing run on the same commit, and a reusable-workflow lane clears only from a caller run at your exact commit.** A newer run that concluded `neutral` is now passed over like a skipped one by `gstack-pregate` and `gstack-ci-carry wait`; a newer failed, cancelled, timed-out or unfinished run still blocks reuse. `gstack-pregate clear --remote <lane> --run-url` on a lane that only runs through `workflow_call` now takes a caller run only when it tested your exact commit. A run of another commit (`head_mismatch`), a pull request run that tested GitHub's merge with the base (`merge_tested`) or a commit whose files differ from what pregate recorded (`tree_mismatch`) is refused, so an old or merged green caller run can't clear today's code. A run of the lane's own workflow is checked as before. Regression tests replay gbrain's real runs at 435e38c5, where a skipped pull request run had blocked a passing manual run.
