- **/ship no longer files deferred review findings as issues.** A blocking finding in code the PR did not change (`review_scope: frozen`) now stays on the PR: `gstack-review-scope defer` records it for the PR body's `## Deferred findings` section and never calls `gh`, so it opens no GitHub issue and needs no marker search. The `--pr`, `--repo`, `--branch` and `--dry-run` options are gone, and a deferred record no longer carries `issue`, `url` or `reason`. When the reviewer stated its own severity or Blocks field, the deferred line in the PR body shows it next to the label, as the issue body used to. /ship's Step 9.4, docs/review-policy.md, docs/ship-policy.md, the READY template, crew/docs/captain.md and the Capy factory page now say the same thing: deferred findings stay on the PR, and follow-up work someone will actually do gets one issue with a named owner. The pre-existing test failure option in /ship that assigns an issue to the person who broke the test is unchanged, since that issue has an owner.
