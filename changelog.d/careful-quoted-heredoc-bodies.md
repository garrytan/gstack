**The destructive-command check no longer asks about text inside a quoted heredoc.** A commit message written with `git commit -F - <<'EOF'`, a `gh issue` or `gh pr` body sent with `--body-file -`, a bare `cat <<'EOF'`, or a small `python - <<'EOF'` script that starts no process could ask for approval because its text mentioned `rm -rf` or `git push -f`. Bash never expands a body with a quoted delimiter, so the check now reads it as text. A body read by a shell, `ssh`, `eval` or a SQL client, an unquoted delimiter, a pipe, and every command outside the body are still checked. Thanks to @nghorbani for the report (#4843).
