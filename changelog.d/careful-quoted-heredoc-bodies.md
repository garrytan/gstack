**The destructive-command check no longer asks about text inside a quoted heredoc that is only read as text.** A commit message written with `git commit -F - <<'EOF'`, a `gh issue` or `gh pr` body sent with `--body-file -`, or a bare `cat <<'EOF'` could ask for approval because its text mentioned `rm -rf` or `git push -f`. Bash never expands a body with a quoted delimiter, so the check now reads such a body as text. A body read by a shell, `ssh`, `eval`, `python` or a SQL client, an editor or exec option, an unquoted delimiter, a pipe, and every command outside the body are still checked. Thanks to @nghorbani for the report (#4843).
