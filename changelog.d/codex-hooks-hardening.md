- **gstack's Codex hooks work when your Codex folder's path has a ( or & in it.** Hook commands for such paths were a shell syntax error, which Codex reads as "block", so every prompt and Bash call was blocked once you trusted the hooks. Both Claude Code and Codex hook commands now quote those paths; plain paths keep the command they had, so nothing asks to be trusted again.
- **Uninstalling gstack keeps your own Codex hooks trusted.** When your hook groups come after gstack's in `hooks.json`, uninstall (and turning a hook off) now leaves an empty group where gstack's was, so your hooks keep the positions Codex trusts them by. If your handler sits inside gstack's group, gstack leaves the file alone and names the one handler to delete.
- **Codex hook setup matches Codex more closely.** `description: null` is accepted, MCP hook input with a null is refused, `rollback` won't restore a backup Codex would skip, a gstack hook already declared in `config.toml` under any matcher that covers Bash is caught, and `gstack-doctor` reads hook trust from the same key Codex uses when `CODEX_HOME` is a symlink.
- **On Windows, gstack's three Codex hooks run instead of silently doing nothing.** Setup now copies the Claude Code hook code they import into Codex's gstack folder.
- **/review's checklist on Codex reads shell commands more carefully.** A `;` inside quotes no longer splits a command, a read that never ran or failed isn't counted, read errors are matched to the exact file, PowerShell's "Cannot find path" counts as one, and a message with only an image starts a new turn.
