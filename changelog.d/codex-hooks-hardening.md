- **gstack's Codex hooks work when your Codex folder's path has a `(`, `&` or other shell character in it.** An unquoted `(` made the hook command a shell syntax error, which Codex reads as "block", so every prompt and Bash call was blocked once you trusted the hooks; an `&` split the command in two. Both Claude Code and Codex hook commands now quote those paths. A path made only of letters, digits and `_ @ % + = : , . / -` keeps the command it had; any other path is quoted once, so Codex asks you to trust those hooks again.
- **Uninstalling gstack keeps your own Codex hooks trusted.** When your hook groups come after gstack's in `hooks.json`, uninstall (and turning a hook off) now leaves an empty group where gstack's was, so your hooks keep the positions Codex trusts them by. If your handler sits inside gstack's group, gstack leaves the file alone and names the one handler to delete.
- **Codex hook setup matches Codex more closely.** `description: null` is accepted, MCP hook input with a null is refused, `rollback` won't restore a backup Codex would skip, a gstack hook already declared in `config.toml` under any matcher that covers Bash is caught (Rust's `(?i)`, `\A` and `\z` included), and `gstack-doctor` reads hook trust from the same key Codex uses when `CODEX_HOME` is a symlink.
- **On Windows, setup copies the Claude Code hook code that gstack's Codex hooks import** into Codex's gstack folder, so the hook scripts are complete. Native Windows Codex still starts hooks through `cmd.exe`, which can't run these Bash scripts, so the hooks don't run there yet.
- **/review's checklist on Codex reads shell commands more carefully.** A `;` inside quotes no longer splits a command, a read that never ran or failed isn't counted, a read error that names another file no longer drops a good read, PowerShell's "Cannot find path" counts as an error, and a message with only an image starts a new turn.
